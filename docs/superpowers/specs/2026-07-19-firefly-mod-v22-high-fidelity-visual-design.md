# Firefly Mod V2.2.2 高保真视觉与功能壳设计

日期：2026-07-19
状态：已获用户批准，待按迁移阶段实施
目标仓库：`null42/null42.github.io`
主视觉参考：`fqzlr/my-blog@65d6daf637e3e3dda460e012b4ef4ff418796dfc`（Firefly Mod V2.2.2）
辅助参考：`MmzMing/my-blog@2fe55d6718839807c5c4cae20c33eae00390cd12`（Firefly Mod V2.5.0）

## 1. 目标

在不改变 `content/` 唯一内容源、不引入 Cloudflare Worker/KV/Vectorize/Workers AI/RAG 的前提下，将现有 Astro 博客从“Firefly 基础风格”提升为以 V2.2.2 为主、V2.5.0 为辅的高保真重构版本。

交付不是静态截图，而是具备真实导航、真实本地播放器、完整首页滚动叙事、静态功能页、无障碍和 Swup 生命周期管理的生产站点。依赖后端或第三方服务的能力只提供完整视觉壳，并明确标注“功能暂未开放”。

## 2. 不可变约束

1. `content/` 是唯一规范内容源。
2. 四级知识规范固定为 `sectionId → routeId → stageId → articleId`。
3. `private`、`hidden`、`encrypted` 严格遵循迁移设计中的公开性矩阵。
4. 加密内容只在浏览器本地解密；解密后使用普通文章相同的 Markdown 渲染与增强管线。
5. 不引入 Cloudflare Worker、KV、Vectorize、Workers AI、RAG 或动态留言后端。
6. 所有全局交互必须在 Swup 往返后保持单实例，可释放 listener、hook、observer、timer、RAF 和媒体对象。
7. 动画必须支持 `prefers-reduced-motion`，核心内容不能依赖动画才可见。
8. 不自动提交、推送或更新 `main`；阶段 8 人工批准门不可跳过。

## 3. 视觉参考优先级

### 3.1 主参考：V2.2.2

- 首次访问的角色加载动画与全屏遮罩。
- 首页大幅角色 Hero、留白比例、低饱和背景、轻拟物卡片和浮动控件。
- 首页由多个全屏或近全屏段落组成的滚动叙事。
- 数据展示、能力矩阵、作品/专题百叶窗和功能入口卡片。
- 相册、日历、友链、音乐等功能页的卡片密度、圆角、阴影和交互节奏。
- 移动端布局收敛为单列内容与底部 Dock，不简单缩放桌面页面。

### 3.2 辅助参考：V2.5.0

- 更完整的 Swup 生命周期和页面加载器控制。
- 音乐可视化、歌词和迷你播放器结构。
- 展示层、百叶窗分层设计和性能边界。
- 新版功能页的无障碍与响应式细节。

若两版发生冲突，视觉构图、色彩和页面密度服从 V2.2.2；生命周期、安全、性能和无障碍实现可采用 V2.5.0 的更成熟方案。

## 4. 首次加载动画

- 首次进入显示全屏加载层，复用已审计参考仓库角色动画素材。
- 原参考品牌文案全部替换为 `null42`，不得保留参考作者身份信息。
- 等待首屏关键图片和字体就绪，但设最大等待时间，失败时也必须释放页面。
- 初次硬加载完整展示；Swup 内部导航使用更短淡入淡出，不重复播放完整动画。
- 显示期间设置 `aria-busy="true"`，隐藏后恢复。
- reduced-motion 下取消位移动画，只保留短淡入淡出或立即显示。
- 控制器必须具备 token/取消机制，连续导航不能让旧异步任务重新显示遮罩。

## 5. 首页滚动叙事

首页采用“Hero → 数据层 → 展示层 → 百叶窗/专题层 → 功能入口 → 最新内容”的连续叙事。桌面端允许 pinned/scrub 动画；移动端转换为正常文档流和简化过渡。

### 5.1 Hero

- 主画面以 V2.2.2 的角色视觉和留白关系为准，不沿用当前工程化 HUD 作为主视觉。
- 品牌内容替换为 `null42`、知识库定位和用户自有文案。
- 保留真实可用的视觉小说式对话框。
- `Back` 回退上一句；`Auto` 自动逐句播放并使用 `aria-pressed`；`Hide` 隐藏/恢复；点击正文区域继续；逐字播放可跳过。
- 状态在当前页面内保持一致，离开首页时完整销毁，重新进入时初始化单一控制器。

### 5.2 数据层

- 使用大字号数字、简短标签、图片与留白形成 V2.2.2 的杂志式数据段落。
- 数据来自构建时统计：公开文章数、知识栏目数、四级覆盖率、附件数量等。
- 不展示无法证明或依赖网络的实时数字。

### 5.3 展示层

- 使用线条生长、文字滑入和中轴扩展形成章节过渡。
- 桌面端可 pin；移动端和 reduced-motion 下显示完整静态构图。
- 文案与图像均配置化，不把参考作者文案写死在组件中。

### 5.4 百叶窗与专题层

- 使用纵向叶片、分层遮罩和主题图像复刻参考站滚动段落。
- 每个专题最终落到真实站内入口，例如 `/knowledge/`、`/list/`、`/gallery/`、`/music/`。
- 动画结束后不得留下覆盖层阻塞链接或键盘焦点。

### 5.5 最新内容与页尾

- 在叙事末端恢复可扫描的文章、知识路线和功能入口。
- 首页即使禁用 JavaScript，也必须保留主要入口和公开内容链接。

## 6. 全局视觉系统

- 使用 V2.2.2 的柔和浅色背景、半透明白色卡片、12–24px 圆角和轻阴影。
- 深色模式不简单反色；保持层次、边框和角色素材可读性。
- 页面最大宽度、卡片间距、标题尺度和移动断点统一为设计 token。
- 导航、Mobile Dock、播放器、加载层和模态共享 z-index 语义表，禁止局部任意抬高。
- 复用参考素材时记录来源、固定 SHA 和 MIT 许可证；不复用参考作者头像、二维码、账号或私人链接。

## 7. 功能页

### 7.1 真实静态功能

- `/music/`：真实本地音频播放器。
- `/gallery/` 与 `/gallery/[album]/`：静态相册、标签筛选、图片查看。
- `/calendar/`：构建时事件数据、月份切换、日期详情。
- `/friends/`：静态友链卡片、规则说明和无网络依赖筛选。
- 现有 `/anime/`、`/bangumi/`：只消费本地静态数据，不在浏览器调用外部 API。

### 7.2 高保真视觉壳

AI 搜索、赞助、动态留言或其他依赖服务的页面：

- 完整复刻面板、标签页、输入区、状态卡和响应式外观。
- 显著显示“功能暂未开放”。
- 控件可展示说明，但不得发送网络请求、写入远端或伪装为已完成。
- 提供普通搜索、GitHub 联系方式或本地内容列表等替代入口。

## 8. 真实本地播放器

- 音频与封面从本地静态目录提供，并进入迁移清单与许可证审计。
- 支持播放/暂停、上一首、下一首、进度跳转、音量、静音、循环模式和播放列表。
- 支持可选歌词；无歌词时提供明确空状态。
- 页面级完整播放器与全局迷你播放器共享同一个 audio 状态。
- Swup 页面切换时音乐不中断；控制器和事件监听不累积。
- 不绕过浏览器自动播放限制；显示可操作的播放提示。
- reduced-motion 下停用频谱和大幅动画，但音频控制保持可用。

## 9. 加密阅读

- 包装页只输出安全元数据、加密载荷 URL 和密码界面。
- 解密后 HTML 使用共享 Markdown 处理器，支持标题锚点、代码高亮、KaTeX、Mermaid、PlantUML、图片网格、GitHub 卡片和邮件保护。
- 注入前执行白名单清理；禁止脚本、事件属性、`javascript:`、`srcdoc` 和 iframe。
- encrypted/hidden 页面保持 `noindex, nofollow`，不输出 `BlogPosting`，不进入 Sitemap/Pagefind。
- Lighthouse 仍审计性能、可访问性和最佳实践，但刻意 noindex 页面不以公开 SEO 阈值阻断。

## 10. 响应式与无障碍

- 验收视口至少为 1440×900、1024×768、768×1024、390×844。
- 所有按钮使用正确语义与可见焦点；切换按钮使用 `aria-pressed`。
- 模态打开时隔离所有非模态分支，关闭、重初始化、Swup 替换和断点切换时恢复原状态。
- 键盘可完成导航、播放器、筛选、对话框、相册和日历主要操作。
- 无 JS 时保留导航、文章链接、知识树基础链接和功能页说明。

## 11. 性能边界

- 首屏角色图使用响应式尺寸和明确宽高，避免布局抖动。
- 首页非首屏图片懒加载；视频默认不预加载媒体内容。
- 大型动画模块仅在对应页面和断点按需加载。
- 不允许因高保真复刻引入常驻多个 animation/observer/controller 实例。
- 生产门继续执行生成泄漏扫描、Pagefind、Sitemap、Lighthouse 和 Playwright 网络边界检查。

## 12. 验收标准

1. 首页与 V2.2.2 的布局层次、色彩、卡片密度和滚动叙事达到明显同源的高保真效果；V2.5.0 只作为能力补充。
2. 首次加载动画、Hero 对话、播放器、相册、日历和友链均有真实交互。
3. AI、赞助等服务型页面为完整视觉壳，明确未开放且零网络请求。
4. 加密文章解密后与普通文章 Markdown 能力一致。
5. 四级知识模型和公开性矩阵不因视觉重构退化。
6. 生产截图与参考基准在桌面、平板、移动端逐页比较，并保存在 `reports/visual-baseline/<date>/`。
7. `quality:full`、全量 Playwright、Lighthouse、`git diff --check` 全部通过。
8. 发布前完成同 SHA 预览、回滚演练和阶段 8 人工批准。
