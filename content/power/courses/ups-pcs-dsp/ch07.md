**本章要解决的问题：** 给系统一个**独立于控制环的"硬测量"**：电网频率与相位。PLL（第29章）是闭环估计，它会"跟着算法走"；eCAP 捕获是直接量时间，可以用来交叉校验、检测异常（丢相、频率越限、PLL 失锁）。本章给出两个精度算例、一段完整的捕获模块代码，以及它与 PLL 的分工。

> [!WARNING]
> 前提：本芯片 eCAP 模块数量与捕获时钟选项属第2章"待核项"，写代码前必须查《TMS320F2807x datasheet (Rev. K)》与《F2807x TRM (Rev. H)》确认可用通道数与预分频范围。下文以"捕获时钟 fcap= 120MHz（预分频 1）"为算例口径。

### 7.1 为什么闭环 PLL 之外还要硬测量

| 手段 | 本质 | 强项 | 弱项 |
| --- | --- | --- | --- |
| SOGI + SRF-PLL | 闭环估计 | 相位连续、抗噪、可跟踪频率变化 | 会"自洽地"给出错误结果（输入异常时仍输出稳定相位） |
| eCAP 捕获 | 开环量时间 | 直接、独立、能发现异常 | 每个过零点才有信息；零交叉噪声直接变成相位抖动 |
| 两者配合 | PLL 跟踪 + 捕获看守 | 既有连续性又有可信度 | 需设计一致性判据（见 7.5） |

> [!IMPORTANT]
> 工程价值：现场最怕的是"PLL 稳、实际电网已经歪了"。捕获测量给出一条独立通道：频率越限（超出 50Hz±10%）、长时间无过零（丢相）、周期突变（切换/扰动）都能在 20ms 量级发现。

### 7.2 算例 7-1：T法测频的精度有多高

```text
思路：量"两个同向过零点之间的时间"，即周期 T，再取倒数得频率。

量程与分辨率（f_cap = 120MHz，标称 50Hz）：
  一个工频周期计数 = 20ms × 120e6 = 2,400,000
  计数分辨率 1 个时钟 = 1/2.4e6 = 0.417 ppm
  频率分辨率 = 50Hz × 0.417e-6 = 20.8 µHz   ← 远超需求（厂站频率考核通常要求 mHz 级）

计数器位宽检查：32 位计数在 120MHz 下回绕时间
  2^32 / 120e6 = 35.8 s  ≫ 20ms  → 不会回绕，无需软件扩展
```

| 方法 | 原理 | 相对误差 | 适用 |
| --- | --- | --- | --- |
| T法（测周期） | 数时钟，测两个事件的时间 | ±1 计数 / 周期计数 = ±0.42 ppm | 工频、低频（本课程采用） |
| M法（测脉冲数） | 固定闸门时间内数事件个数 | ±1 事件 / 事件数（闸门越短越差） | 高频、快速变化 |
| M/T 组合 | 同时数事件与时钟 | 兼顾快与准 | 频率范围宽且要求快的场合 |

### 7.3 算例 7-2：相位测量的实际精度由谁决定

```text
计数分辨率给出的理论相位精度：
  1 计数 / 2,400,000 计数 × 360° = 0.00015°     ← 理论值，实际远达不到

实际瓶颈是过零检测的噪声：设 311V 峰值、过零处噪声 0.5V
  过零斜率 = 2π·50·311 = 97,700 V/s
  等效时间抖动 = 0.5V / 97700 V/s = 5.1 µs
  折算相位抖动 = 5.1µs / 20ms × 360° = 0.092°

结论：相位精度由模拟前端（过零比较器/滤波）决定，不由计数器决定。
      想提高精度 → 加过零滤波/迟滞（代价：引入相位偏移，需要标定补偿）
```

### 7.4 捕获模块代码（可直接编译的模块）

```c
/* ---------- param_table.h 相关常量 ---------- */
#define CAP_CLK_HZ      120000000.0f   // Hz，捕获时钟（预分频 1，第2章规格）
#define GRID_F_NOM      50.0f          // Hz，标称工频
#define GRID_F_MIN      45.0f          // Hz，频率下限（规范：50Hz±10%）
#define GRID_F_MAX      55.0f          // Hz，频率上限
#define CAP_TIMEOUT     30e-3f         // s，丢失捕获判定（1.5 倍工频周期，第7章 7.2）
#define CAP_N_AVG       4              // 周期滑动平均长度（抑制单次抖动）

/* ---------- cap.h ---------- */
typedef struct {
    volatile uint32_t t_last;      // 上一次捕获计数
    volatile uint32_t period[CAP_N_AVG];
    volatile uint8_t  idx;
    volatile uint8_t  evt_count;   // 连续捕获事件计数（4 事件一帧）
    volatile float    f_hz;        // 测量频率（已滤波）
    volatile float    phase_deg;   // 相对 PWM 载波零点的相位（度）
    volatile uint16_t flags;       // CAP_F_VALID / CAP_F_LOST / CAP_F_RANGE
} cap_t;
extern cap_t g_cap;

/* ---------- cap.c ---------- */
void cap_init(void)
{
    // 依次配置：捕获模式=连续 4 事件、边沿=上升沿、捕获时钟预分频=1
    // 具体寄存器名以《F2807x TRM (Rev. H)》eCAP 章节为准（第2章待核项）
    CAP_setMode(CAP_BASE, CAP_MODE_CONT_4EVT);
    CAP_setEdgePolarity(CAP_BASE, CAP_RISING);
    CAP_setPrescaler(CAP_BASE, 1);
    CAP_enableInt(CAP_BASE);          // 捕获事件中断
    Interrupt_enablePIE(INT_CAP);     // 组使能（组号以 TRM 为准）
}

/* 捕获中断：连续 4 事件 → 一帧，用 4 个时间戳算周期与占空比 */
__interrupt void cap_isr(void)
{
    const uint32_t t = CAP_readTime(CAP_BASE);   // 读捕获时间戳（计数）

    if (g_cap.evt_count == 0) {
        g_cap.t_last = t;                        // 第 1 事件：记起点
    } else {
        const uint32_t dt = t - g_cap.t_last;    // 无符号减法自动处理回绕
        g_cap.t_last = t;
        g_cap.period[g_cap.idx] = dt;
        g_cap.idx = (uint8_t)((g_cap.idx + 1) % CAP_N_AVG);
    }

    if (++g_cap.evt_count >= 4) {               // 一帧完成 → 计算
        g_cap.evt_count = 0;
        uint32_t sum = 0;
        for (uint8_t k = 0; k < CAP_N_AVG; k++) sum += g_cap.period[k];
        const float t_period = (float)sum / (CAP_N_AVG * CAP_CLK_HZ);   // 平均周期(s)
        const float f = 1.0f / t_period;                                 // 频率(Hz)

        if (f < GRID_F_MIN || f > GRID_F_MAX) {
            g_cap.flags |= CAP_F_RANGE;          // 频率越限 → 交状态机处理
        } else {
            g_cap.flags |= CAP_F_VALID;
            g_cap.flags &= (uint16_t)~CAP_F_RANGE;
        }
        g_cap.f_hz = f;

        // 相位：捕获时刻与 PWM 时基零点的差 → 折算成电角度
        // 时钟域注意：t 与 sum 是 eCAP 计数（f_cap = 120MHz），而 EPWM_readCounter 读到的
        // TBCTR 是 ePWM 时基计数（EPWMCLK = 60MHz，增减模式每载波周期 0→3334 回绕），
        // 两者时钟频率与回绕原点均不同，不能直接相减；须先把 TBCTR 换算到同一时钟
        // （×f_cap/EPWMCLK = ×2），并保证与 t 对齐到同一回绕原点后再相减：
        const uint32_t tpwm = (uint32_t)EPWM_readCounter(EPWM_GRID_SYNC) * 2u;   // 60MHz → 120MHz 同口径
        const float dt_deg = (float)(t - tpwm) / (float)sum * 360.0f;
        g_cap.phase_deg = dt_deg;
    }

    CAP_clearIntFlag(CAP_BASE);                  // 三件套：清外设标志
    Interrupt_clearACKGroup(INT_CAP);            //        应答 PIE 组
}

/* 慢任务（1ms）里做超时判定与告警，不占用捕获中断 */
void task_cap_watchdog(void)
{
    static uint32_t last_evt_cnt = 0;
    static uint16_t ms_idle = 0;

    if (g_cap.evt_count == last_evt_cnt) {        // 本毫秒没有新捕获
        if (++ms_idle > (uint16_t)(CAP_TIMEOUT * 1000.0f)) {
            g_cap.flags |= CAP_F_LOST;            // 丢相/无过零 → 告警并降级
            ms_idle = 0;
        }
    } else { last_evt_cnt = g_cap.evt_count; ms_idle = 0; g_cap.flags &= (uint16_t)~CAP_F_LOST; }
}
```

> [!TIP]
> 代码要点：①捕获中断只做"记时间戳 + 简单累加"，计算放在帧结束的那一次，保证 ISR 恒定短；②超时判定放 1ms 慢任务（第4章纪律），它不影响实时性；③用无符号减法算时间差，天然处理计数器回绕。

### 7.5 与 PLL 的一致性判据（把硬测量用起来）

```c
/* 1ms 慢任务中执行：交叉校验 PLL 与捕获测量 */
void task_pll_sanity(void)
{
    if (!(g_cap.flags & CAP_F_VALID)) return;          // 捕获未就绪 → 不做判据
    const float f_pll = pll_get_frequency();            // PLL 估计频率(Hz)
    const float f_cap = g_cap.f_hz;                     // 捕获测量频率(Hz)
    const float err   = fabsf(f_pll - f_cap);

    if (err > 0.2f) {                                   // 0.2Hz 阈值（第29章带宽与 2ω 纹波权衡）
        g_prot.fault |= PROT_F_PLL_MISMATCH;            // 记录故障码，交状态机决策
    }
    if (g_cap.flags & CAP_F_LOST) {                     // 捕获长时间无事件
        g_prot.fault |= PROT_F_GRID_LOST;
    }
}
```

| 判据 | 阈值 | 来源 | 动作 |
| --- | --- | --- | --- |
| PLL 与捕获频率偏差 | >0.2Hz 持续 100ms | 第29章 PLL 带宽与纹波权衡 | 记录故障码；必要时降带宽 |
| 频率越限 | 超出 45~55Hz | 规范输入频率 50Hz±10%、频率跟踪 ±4% | 按第34章状态机转电池/旁路 |
| 长时间无过零 | >30ms 无捕获事件 | 1.5 倍工频周期 | 判丢相，禁切旁路、保持当前模式 |
| 周期突变 | 相邻帧周期差 >5% | 切换/扰动特征 | 清 PLL 积分器，走重锁流程 |

### 7.6 算例 7-3：频率跟踪速率限幅怎么实现

```text
规范要求：频率跟踪速率 0.5~2 Hz/s（见整机验收指标表 A 组）

控制中断 9kHz（奇偶双拍，每 2 载波中断一次）下，每拍允许的最大频率变化：
  Δf_max = 2 Hz/s ÷ 9000 拍/s ≈ 0.222 mHz/拍

实现（在 PLL 输出侧限幅，防止电网扰动被"全速跟踪"成输出频率跳变）：
  float df = f_new - f_prev;
  const float df_max = 0.222e-3f;                 // Hz/拍，来自上式
  if (df >  df_max) df =  df_max;
  if (df < -df_max) df = -df_max;
  f_out = f_prev + df;
```

> [!IMPORTANT]
> 为什么要限速：不限速时，电网一次瞬时扰动会让输出频率跟着跳，负载（尤其是电机类）会受冲击；规范把这个速率写成了硬指标。限速的代价是"电网真的变频时跟踪变慢"，因此 0.5~2 Hz/s 的取值要在"抗扰"与"跟随"之间选，一般取 1 Hz/s 附近。

### 7.7 上机核对（LAB0/LAB4）

| 步骤 | 该看到什么 | 判据 |
| --- | --- | --- |
| 信号源注入 50.00Hz | `g_cap.f_hz` 显示 50.00Hz | 误差 <±20 mHz（算例 7-1 的分辨率余量充足） |
| 注入 49.0/51.0Hz | 读数跟随，越限标志不置位 | 误差 <±20 mHz |
| 注入 44Hz / 56Hz | `CAP_F_RANGE` 置位 | 按 45~55Hz 边界动作 |
| 拔掉输入 | 30ms 后 `CAP_F_LOST` 置位 | 告警可复现 |
| 相位与示波器比对 | 捕获相位与示波器过零时刻一致 | 偏差 <0.5°（过零噪声决定） |

### 7.8 失败案例复盘：一次丢捕获让 PLL"越跑越偏"

> [!CAUTION]
> 现象：现场偶发输出频率缓慢漂移到 51Hz，20 秒后自行恢复。定位路径：①看捕获日志（发现某段时间捕获事件数为 0）→ ②查输入（过零比较器供电瞬断）→ ③看 PLL（无硬测量校验，PLL 按自己的积分器继续"跟踪"了一个错误参考）→ ④补上一致性判据后，同类故障在 100ms 内被记录并降带宽。根因：只有闭环估计、没有独立校验通道；PLL 的"自洽"掩盖了输入异常。预防措施：①必须实现 7.5 的三条一致性判据；②捕获丢事件只告警不静默；③把"PLL 与捕获偏差"纳入遥测（第41章），现场可回溯。

### 7.10 练习

1. **E1** 捕获时钟改为 60MHz，标称 50Hz：求周期计数值与频率分辨率；若要求 1 mHz 精度，是否满足？
2. **E2** 过零噪声 1.0V、峰值 311V、50Hz：求相位抖动（度）；若在过零前加一级 200Hz 低通，抖动与相位偏移各是多少（提示：偏移 = atan(50/f_p)）？
3. **E3** 用 7.6 的代码，把跟踪速率设为 0.5Hz/s 与 2Hz/s，分别计算"电网从 50Hz 变到 51Hz 需要多久跟上"，并说明各自适用场景（参考答案见 [练习参考答案](/posts/power/courses/ups-pcs-dsp/docs/answers/)）。
