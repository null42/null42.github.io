**本章要解决的问题：** 把"浮充、均充、限流充电"三段策略与 BMS 的限值协同起来，并处理最危险的两个工况：拉弧 与 主动脱扣。

### 43.1 三段式充电与限值来源

| 阶段 | 判据 | 电压（384V 组，2V/单体 192 串） | 电流 |
| --- | --- | --- | --- |
| 限流恒流 | SOC <90% 或电压低于浮充值 | — | ≤0.1C（10A，第34章回充口径） |
| 均充（均衡） | 周期触发（90 天）或单体压差 >50mV | 2.35V/单体 → 451V | 降至 0.02C 后转浮充 |
| 浮充 | 均充结束后长期维持 | 2.25V/单体 → 432V | ≈0（补偿自放电） |

### 43.2 算例 43-1：限流充电的功率与母线协同

```text
充电电流 0.1C = 10A，电池 384V → 充电功率 = 3.84 kW
  同时供给负载 30kW → 整流器输出需 30 + 3.84/0.98 = 33.9 kW
  若整流器额定 50kW → 系统负载率 = 68% ✓
  若负载升到 48kW 且仍充电 → 超出！必须按优先级：
    ① 负载优先：先满足负载
    ② 充电降流：负载 >85% 时充电电流降到 0.05C（5A），>95% 时暂停充电
    ③ 恢复条件：负载 <80% 后 60s 恢复原充电电流（避免频繁抖动）

  定量：负载 48kW 时整流器需 48/0.956 = 50.2kW 已满 → 充电必须暂停（0A）
  判据：任何负载下都不发生"母线电压跌落 >5%"；充电暂停/恢复不得引起负载侧扰动 >2%
```

### 43.3 算例 43-2：主动脱扣与拉弧防护

```text
直流侧最危险的工况：带载断开电池断路器 → 直流电弧（无自然过零，可持续燃烧）
  400V/139A 直流回路的电弧能量：若电弧维持 20ms → E = 400×139×0.02 = 1,112 J（足以引燃）

  防护三层：
    ① 顺序：先降流（DC-DC 把电流降到 <10A）再分断 → 电弧能量降到 400×10×0.02 = 80 J
    ② 主动脱扣（远程联动）：BMS/主控检测到拉弧、高温、绝缘下降 → 发脱扣信号给带分励脱扣器的断路器
       动作时间 ≤20ms；并由熔断器做后备（I²t 配合）
    ③ 硬件：断路器按直流额定（不是交流额定）选型；电缆固定、端子力矩标准化

  与 BMS 的接口（本课程口径）：
    主控 → BMS：充放电允许、电流限值、均充请求
    BMS → 主控：允许充/放电、最大电流、单体最高/最低压、最高温、绝缘状态、SOH、告警码
    通信周期 ≤1s；通信中断 3s 后主控自动降流到 0.05C 并告警（保守策略）
```

### 43.4 算例 43-3：BMS 限值与主控限值的"取小"原则

```text
两套限值可能冲突，规则是"取更保守者"：
  放电最大电流：DC-DC 能力 160A；BMS 报允许 120A（因单体温度 45℃）→ 取 120A
  充电最大电流：主控设定 10A（0.1C）；BMS 报 8A（因单体压差大）→ 取 8A
  母线电压上限：主控 805V；BMS 报电池侧 460V 对应母线 470V → 取更小

  实现要点：
    ① 每次通信收到新限值后"立即生效"（不能只在启动时读一次）
    ② 限值变化必须限速（例如电流限值 1s 内变化 ≤20%），避免突变导致母线波动
    ③ 限值失效（通信超时）→ 回退到"出厂保守值"而不是"上一次值"（防止用旧的高限值）
  判据：BMS 限值突变测试下，母线电压波动 ≤2%、电池电流无冲击
```

### 43.5 代码：充电管理状态机与限值合成

```c
/* ---------- charge.c ---------- */
#define CHG_IC_MAX_A      10.0f        /* 0.1C（43-2 ①） */
#define CHG_IC_REDUCED_A   5.0f        /* 0.05C（负载高时） */
#define CHG_V_EQUALIZE_V 451.0f        /* 均充电压（2.35V/单体） */
#define CHG_V_FLOAT_V    432.0f        /* 浮充电压（2.25V/单体） */
#define CHG_BMS_TIMEOUT_MS 3000u       /* BMS 通信超时 → 保守降流 */
#define CHG_LIM_RATE_S    20.0f        /* 限值变化速率上限（%/s，43-4 ②：1s 内 ≤20%） */

typedef enum { CHG_IDLE=0, CHG_CC, CHG_CV_EQUAL, CHG_FLOAT } chg_state_t;

typedef struct {
    float i_lim_a, v_target_v;         /* 合成后的限值（取小） */
    chg_state_t st; uint32_t t_ms;
} chg_t;
static chg_t g_chg;

/* 限值合成：主控能力 ∩ BMS 限值 ∩ 出厂保守值（43-4） */
void chg_update_limits(float i_cap, float i_bms, float v_ctrl, float v_bms)
{
    float i_new = fminf(i_cap, i_bms);
    float v_new = fminf(v_ctrl, v_bms);
    if (g_comm.bms_lost_ms > CHG_BMS_TIMEOUT_MS) { i_new = CHG_IC_REDUCED_A; }   /* 保守回退 */
    /* 限速（43-4 ②）：20%/s，每 10ms 一步 → 每步步进 0.2%（i_step = 0.002f*i_lim），
       100 步 × 0.2% = 20% → 1s 内变化 ≤20%（每 10ms 调用一次） */
    const float i_step = CHG_LIM_RATE_S * 0.01f * 0.010f * g_chg.i_lim_a;        /* 20%/s × 10ms = 0.2%/步 */
    g_chg.i_lim_a += clampf(i_new - g_chg.i_lim_a, -i_step, i_step);
    g_chg.v_target_v = v_new;
}

/* 10ms 任务：充电状态机 */
void task_charge(void)
{
    const float load = sys_load_ratio();
    switch (g_chg.st) {
    case CHG_IDLE:
        if (g_cmd.charge_req && bms_allow_charge()) { g_chg.st = CHG_CC; g_chg.t_ms = 0; }
        break;
    case CHG_CC:                                    /* 恒流 */
    {
        float i_cmd = g_chg.i_lim_a;
        if (load > 0.95f) i_cmd = 0.0f;                   /* 负载 >95% → 暂停充电（43-2 ②，与 FLOAT 同条件） */
        else if (load > 0.85f) i_cmd = 0.5f * g_chg.i_lim_a;   /* 负载优先：降到 0.05C */
        dc_dc_set_current(i_cmd);
        if (battery_voltage() >= CHG_V_EQUALIZE_V) { g_chg.st = CHG_CV_EQUAL; g_chg.t_ms = 0; }
        break;
    }
    case CHG_CV_EQUAL:                              /* 均充恒压 */
        dc_dc_set_voltage(CHG_V_EQUALIZE_V);
        if (battery_current() < 0.02f*BATT_CAP_AH && ++g_chg.t_ms > 3000u) g_chg.st = CHG_FLOAT;
        break;
    case CHG_FLOAT:                                 /* 浮充 */
        dc_dc_set_voltage(CHG_V_FLOAT_V);
        if (load > 0.95f) dc_dc_set_current(0.0f);  /* 负载过重 → 暂停充电（43-2 ②） */
        break;
    }
}

/* 主动脱扣：严重故障时先降流再分断（43-3） */
void batt_emergency_open(void)
{
    dc_dc_set_current(0.0f);                        /* ① 降流到 0 */
    task_delay_ms(50);                              /* ② 等电流消失（限 50ms） */
    batt_breaker_remote_trip();                     /* ③ 分励脱扣 */
    log_fault_event(EV_BATT_TRIP, 0u);
}
```

### 43.6 上机核对（LAB5）

| 步骤 | 该看到什么 | 判据 |
| --- | --- | --- |
| 三段充电 | 电流/电压曲线 | 0.1C 恒流 → 均充恒压 → 浮充（43-2） |
| 负载优先 | 负载 90% 时充电电流 | 自动降到 0.05C |
| BMS 限值突变 | 母线电压波动 | ≤2%（限值限速生效，43-4 ②） |
| BMS 断线 | 充电行为 | 3s 内降流到 0.05C 并告警 |
| 主动脱扣 | 带载分断的电流波形 | 分断前电流 ≤10A，无拉弧痕迹 |
| 单体压差告警 | 模拟压差 60mV | 自动转均充或告警 |

### 43.7 失败案例复盘：带载直接分断电池断路器，端子烧蚀

> [!CAUTION]
> 现象：维护时按下电池断路器分闸按钮，出现剧烈电弧，断路器与端子烧蚀，电池组报废。定位路径：①现场还原（带载 100A 直接分断）→ ②核算电弧能量（43-3：约 1.1 kJ）→ ③确认系统没有"先降流后分断"的顺序，也没有分励脱扣联动 → ④加顺序控制 + 主动脱扣 + 操作规程后不再发生。根因：直流无自然过零，带载分断必然拉弧；系统缺少"降流 + 联动脱扣"的保护设计。预防措施：①软件必须提供batt_emergency_open()式顺序停机；②断路器选直流型号并配分励脱扣；③操作面板与说明书必须写明"先停机再分闸"；④把"带载分断试验"（低压小电流）纳入 LAB5。
