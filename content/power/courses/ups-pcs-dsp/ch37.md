**本章要解决的问题：** 把前面 36 章的功能装进一颗 120MHz 的 DSP 且不打架：任务分层、WCET 预算、参数表 与 CRC、以及让现场可诊断的日志体系。

### 37.1 任务分层（本课程固定架构）

| 层 | 周期 | 内容 | 纪律 |
| --- | --- | --- | --- |
| ISR-A（控制） | 111.1µs（9kHz，每 2 载波一次，参考工程 INTPRD=ET_2ND 口径） | 第4章"五件事"：采样→控制→限幅→写 PWM→清标志 | 只做确定的事，禁止分支深、禁浮点除法、禁通信 |
| ISR-B（保护） | 事件（TZ/故障） | 封波、记录快照 | ≤200 周期，不做决策 |
| 任务 T1 | 1ms | 状态机、保护决策、PLL 监视、遥测采样 | 单次 ≤200µs |
| 任务 T2 | 10ms | 滤波/谐波分析、BMS 交互、温度 | 单次 ≤1ms |
| 任务 T3 | 100ms/1s | 通信上报、日志落盘、自检 | 不得阻塞以上任务 |

### 37.2 算例 37-1：ISR 时间预算表（逐项可核对）

```text
18kHz 周期 = 120MHz/18kHz = 6,667 周期

 项目 平均 最坏
 ADC 读取与换算（6 通道） 120 180
 PLL（含三角函数） 300 340
 电流环 PI（dq 两路） 160 200
 解耦 + 前馈 + 阻尼 200 260
 SVPWM（扇区+时间+写比较） 260 320
 保护快环 120 180
 状态记录/计数 80 100
 ISR 进出与上下文保存 180 220
 ────────────────────────────────────────────
 合计 1,420 1,800
 加上第13章的单相逆变（PR + 谐振器组）增量：
 4 个谐振器（每个 ~40 周期） 160 200
 提取/补偿（MSRF 4 次） 400 600
 ────────────────────────────────────────────
 合计 1,980 2,600 → 占 14.9% / 19.5%

分母 = 控制中断周期 111.1µs = 13,333 计数（9kHz 双拍口径，与第2/4章一致）：
 1,980/13,333 = 14.9%（平均）、2,600/13,333 = 19.5%（最坏）
若启用双更新（第21章，每半载波一次）：预算改为 3,333 周期 → 最坏 2,600 仅剩 733 周期余量
 ——这正是本课程选"奇偶双拍分摊"（37.9）而不是双更新的原因
```

### 37.3 算例 37-2：WCET 纪律与占用率上限

```text
为什么占用率上限取 50%（本课程口径）：
 ① 中断可能嵌套（TZ 打断控制 ISR）→ 需要"最坏叠加"空间
 ② WCET 估计本身有误差（分支、缓存/流水线、编译器优化）——通常低估 10~30%
 ③ 现场偶发条件（通信中断、BMS 超时）会让同一函数走到更坏路径

 定量：控制 ISR 最坏 2,600 + TZ 最坏 400 = 3,000 周期
 占控制中断周期 13,333 的 22.5%；若再叠加一次 ADC 中断（EOC）200 周期 → 24.0% < 50% 
 若占用率接近 70%：一旦有偶发嵌套就会出现"ISR 超时"→ PWM 更新错过 → 输出畸变
 监测手段：ISR 内 GPIO 打点 + 统计最大/平均时长（第3章），并在遥测里上报
```

### 37.4 算例 37-3：参数表、CRC 与烧写可靠性

```text
参数块大小：512 B（≈128 个 float 参数），双备份（A/B 区）
 CRC16 计算量：约 4 周期/字节 → 512×4 = 2,048 周期 = 17 µs（上电时算，不进 ISR）
 校验策略：
 ① 上电：算 A 区 CRC → 与存储值比对 → 失败则用 B 区 → 都失败则用出厂默认
 ② 运行中：每 10s 复算一次（后台任务），发现不一致立即报 PROT_F_PARAM_CRC 并禁止带载
 ③ 写入：先写 B 区 → 校验 → 再写 A 区（掉电安全）

 关键参数保护：过流阈值/母线过压阈值/限幅值等"保护类参数"单独放一个小块，
 并加"范围表"校验（例如 270A 必须落在 [100A, 400A]）——防止被改成 10A 或 10000A
 实测数据：某现场误把过流阈值改成 30A 导致频繁切旁路；加范围校验后此类事故归零
```

### 37.5 代码：调度骨架与参数表

```c
/* ---------- tasks.c：极简时间触发调度（不用 RTOS 的场合） ---------- */
typedef struct { uint16_t period_ms; uint16_t next_ms; void (*fn)(void); const char *name; } task_t;

static task_t g_tasks[] = {
 { 1, 0, task_sys_fsm, "fsm" }, /* 状态机（第34章） */
 { 1, 0, task_prot_decide, "prot" }, /* 保护决策（第36章） */
 { 1, 0, task_pll_watchdog, "pllwd" }, /* PLL 监视（第29章） */
 { 10, 0, task_harm_report, "harm" }, /* 谐波遥测（第23章） */
 { 100, 0, task_comm_report, "comm" }, /* 通信上报（第40章） */
 {1000, 0, task_param_crc_check, "pcrc" }, /* 参数表 CRC（37-4） */
};
static uint16_t g_ms_tick;

void task_dispatch(void) /* 由 1ms 定时中断调用 */
{
 g_ms_tick++;
 for (uint8_t k = 0; k < ARRAY_LEN(g_tasks); k++) {
 task_t *t = &g_tasks[k];
 if (g_ms_tick >= t->next_ms) {
 t->next_ms = g_ms_tick + t->period_ms;
 task_wdt_start(t->name);
 t->fn();
 task_wdt_stop(t->name); /* 超时则记录并降级（不阻塞后续） */
 }
 }
}

/* ---------- param.c：参数表双备份 + 范围校验 ---------- */
typedef struct { float val, min, max; } param_range_t;
static const param_range_t PARAM_RANGE[] = {
 [P_PARAM_OC_TZ] = { 270.0f, 100.0f, 400.0f }, /* 过流阈值（36-2） */
 [P_PARAM_VBUS_OV]= { 805.0f, 700.0f, 900.0f }, /* 母线过压 */
 [P_PARAM_ILIM] = { 110.0f, 50.0f, 200.0f }, /* 电流限幅 */
};

uint8_t param_write(uint16_t id, float v)
{
 if (id >= P_PARAM_COUNT) return 1u;
 const param_range_t *r = &PARAM_RANGE[id];
 if (v < r->min || v > r->max) return 2u; /* 范围校验：拒绝不合理值 */
 param_store_b(id, v); /* 先写 B 区 */
 if (param_crc16(AREA_B) == param_crc_stored(AREA_B)) param_store_a(id, v);
 return 0u;
}
```

### 37.7 失败案例复盘：慢任务阻塞，ISR 错过 PWM 更新

> [!CAUTION]
> 现象：运行若干小时后偶发输出波形畸变（每一两个月一次），复位后恢复；日志无异常。定位路径：①抓畸变时刻的波形（PWM 比较值少更新一拍）→ ②查任务时长统计（T2 偶发跑到 8ms）→ ③定位原因（BMS 通信重试循环：串口等待超时未加限次）→ ④改为"状态机式非阻塞通信"后消失。根因：低优先级任务里存在阻塞等待（串口/BMS），一旦超时就长时间占用 CPU，挤掉控制 ISR 的预算。预防措施：①所有外设访问必须非阻塞（状态机 + 超时退出），禁止while(等待)；②给每个任务加看门狗计数（超时即记录并跳过）；③把"ISR 时长最大值"纳入遥测长期监视，异常时自动记录快照。

### 37.9 平台级四项工程做法：CLA 分工、软件 trace、分段耗时、奇偶拍分工

这四项不改变算法数学，但决定"算力够不够、现场能不能定位"。它们全部来自主参考工程（[参考代码索引](/posts/power/courses/ups-pcs-dsp/docs/reference-code/) 第 0.2 节），本节给出可执行的纪律。

#### ① CLA 分工与 CPU↔CLA 数据交换

```text
CLA（Control Law Accelerator）是独立协处理器：不经过 PIE、由任务触发、可与 CPU 并行执行
参考工程的做法：θ 与采样数据处理放在 CLA，CPU 只做取回与决策
 CPU → CLA：APP_Int_ToClaThetaDataDeal()、APP_Int_PrimaryToClaDataDeal()
 CLA → CPU：APP_Int_FromClaDataDeal()（注释实测 1.22µs，"放这个位置是为了等 CLA 里面的采样数据出来"）

分工判据（本课程口径）：
 放 CLA：周期性、可预测、无分支的计算 —— Clarke/Park 变换、SVPWM 占空比、定系数滤波
 留 CPU：决策、状态机、保护判定、通信、参数存取（这些都带分支与外部依赖）
数据交换纪律（与第40章双缓冲同源）：
 共享 RAM + 序号握手：写侧写完置序号，读侧读前后各读一次序号，相同才使用；
 共享区禁止跨任务就地修改，必须"整块发布"
代价与风险：CLA 不能打断点，只能靠镜像变量 + trace + 示波器（DAC/GPIO 打点）观察；
 因此 CLA 内的中间量必须周期性镜像到 CPU 可读区域
```

#### ② 软件 trace（跑到哪个函数了）

```text
参考工程做法（贯穿整个 ISR）：
 INT_RUN_PREVIOUSFUNCTION = INT_RUN_FUNCTION; // 保留上一位置
 INT_RUN_FUNCTION = 0x8001; // 0x8001 = 逆变同步记录，0x8003 = 后续段
使用方式：死机、看门狗复位、TZ 动作后，先读这两个全局变量，直接得到"最后执行位置"
成本：每条 2 个赋值指令（可忽略）；建议按模块分段编号：
 0x80xx 逆变算法 / 0x81xx 通信 / 0x82xx 母线 / 0x83xx 旁路 / 0x84xx 保护
与黑匣子（第36章）配合：故障快照里同时记录 INT_RUN_FUNCTION，定位时间从"几小时"降到"几分钟"
```

#### ③ ISR 分段实测耗时标注

```text
参考工程在每个 ISR 内调用旁都标了实测值（真实数据）：
 485 通信 平均 1.8µs / 最大 4.6µs / 最小 0.2µs（注意：这一段在 ISR 内，见 ④ 的边界条件）
 DCBusPreDeal 0.3µs；FromClaDataDeal 1.22µs；BpPreDeal 1.045µs；OutPreDeal 0.428µs；PulseChange 0.8µs
测量手段：ISR 入口用 ReadCpuTimer0Counter()（或 eCAP1 的 TSCTR）读起点，出口读终点，差值×时钟周期得 µs

纪律（写进代码评审检查单）：
 ① 每个 ISR 内函数在调用行上方注明"平均/最坏 µs"与测量条件（负载/工况）
 ② 采样 ≥1000 次并给出最坏值（平均值会掩盖超时路径）
 ③ 数值同时录入设计文档，作为 WCET 的证据（第37章 37-3 的占用率上限以此为输入）
 ④ 任何逻辑变更后必须重测并更新注释；注释过期等于没有测量
```

#### ④ 奇偶拍分工

```text
参考工程用 g_i16_IntCnt1Per2_0 把重活分摊到相邻两拍：
 == 1 的拍：时钟维护、主程序接口 2（输入数据处理）
 != 1 的拍：Alg_Int_PulseChange()（逐波限流值修正）、objBalancer.Dat_Int_IBalPreDeal()（母线平衡电流）
作用：把 ISR 最坏时长压到单拍可承受范围内（第36章 36-10 的逐波限流值修正属"每 2 拍一次"）
必须写进时序说明：**被分摊的功能每 2 个控制中断才更新一次**（本例：18kHz 载波、9kHz 控制中断 → 更新率 4.5kHz）；
 调试时若发现"响应慢一拍"，先查这里，而不是先改补偿器
与第21章"双更新"的区别（别混）：
 双更新 = 每半载波周期算一次并立即更新（提高控制带宽，减延迟）
 奇偶拍分工 = 相邻两个控制中断（奇/偶拍）承担不同功能（降低单次最坏时长）
```

> [!WARNING]
> 关于"通信要不要放进 ISR"：参考工程把 485 通信放在 9kHz 的 ePWM 中断里，实测平均 1.8µs、最大 4.6µs。本书第37章的原则（通信不进 ISR、改放 10ms/100ms 任务）针对的是"可能阻塞的通信"（等待应答、重传、Flash 写入）。判断标准只有一条：这段通信的最坏耗时是否可界且已实测。若可界（例如定长报文的发送缓冲搬运），放进 ISR 换取时序确定性是合理的；若不可界（等待回复、协议栈重试），必须移出。两种做法都要有实测数据支撑。

### 37.11 补充：CLA 侧的实现约定（对照 逆变侧28075CLA内容.cpp）

参考工程的 CLA 侧是一个 1,623 行的中断任务 `ClaTask1`（由 `ADCINT1` 触发），其内部约定与 CPU 侧不同，是"把一段实时链搬进协处理器"的最低要求。

#### ① 任务内的执行顺序（顺序即数据依赖）

```text
Drv_CLA_PWMSOCSEL() 设置载波上升/下降沿触发采样（三组 ADC 的采样点分配）
Drv_CLA_SamplingCHFixedData() 固定通道采样数据读取（Vouta / VBPA / Ibal / Vnpgnd / VINDC_A）
Dat_CLA_InvPreDeal() 逆变侧前置处理
Drv_CLA_SamplingCHVariedData() 可变通道处理 + 切换采样通道（Ila1 / Ila2 等轮流采样）
Dat_CLA_FromCpuThetaDataDeal() 接收 CPU 送来的角度数据（锁相在 CPU 侧做）
Alg_CLA_PhaseAngleCalc() 相位角计算
Alg_CLA_VoltReg() 电压环
Alg_CLA_CurrReg() 电流环
Alg_CLA_VIModeReg() 电压-电流模式调节
Dat_CLA_SPWM() 调制（含 SVPWM 与直流分量补偿）
Alg_CLA_HarmAngleCal() 谐波相角计算
Alg_CLA_VinvHarmCmpn() 输出电压谐波补偿
Dat_CLA_InvOffReset() 停机复位
顺序不能重排：相位角在前、双环居中、调制在后、复位收尾；任何一环依赖前序输出
```

#### ② 命名三段式（CLA 版）

| 前缀 | 含义 | 本书对应（第37章 37.10） |
| --- | --- | --- |
| `Drv_CLA_` | 驱动/外设交互（采样点设置、通道切换） | `adc_` / `pwm_` |
| `Dat_CLA_` | 数据处理（定标、限幅、模式判别） | `ctrl_` 内的数据准备部分 |
| `Alg_CLA_` | 算法（相位、双环、谐波补偿、调制） | `ctrl_` |

同一功能在 CPU 侧与 CLA 侧各有一份实现（如 `Alg_CLA_CurrReg` 与 CPU 侧的电流环），**两侧的系数必须来自同一个参数表**（第37章 37.7），否则"调试时改一侧忘记改另一侧"就是最难查的一类问题。

#### ③ CPU 与 CLA 的数据接口

```text
共享区命名（参考工程）：
 CPUtoCLAVar CPU 写、CLA 读（指令、模式标志、参数、角度）
 CLAVar CLA 本地中间量（不外送）
 Cla1ToCpuMsgRAM 消息 RAM，地址范围见注释 [0x1480, 0x80]（128 字）
标志结构体：Flag1.bInvOnFlag（逆变开机）、Flag2.bNoServiceMode（非工装模式）
 任务内的条件执行：仅当"非工装模式 且 逆变开机"时才跑算法，其余情况只做安全收尾
三条纪律（缺一条就会出偶发故障）：
 ① 单向写入：CPUtoCLAVar 只由 CPU 写，CLA 只读；避免双向写同一变量
 ② 一致性：多字节/多量组成的"一组数据"必须用序号或标志位成组更新（第37章 37.9 奇偶拍同理）
 ③ 触发与清除：CLA 任务由 ADCINT1 触发，CLA 不自动清标志，任务末必须手动清
 AdcaRegs.ADCINTFLGCLR.bit.ADCINT1 = 1; // 不清则任务重复触发
```

#### ④ 在 CLA 里写代码的四条注意

```text
① 浮点做逻辑判断：写 (x > 0.5) 而不写 (x == 1.0)——浮点精度问题；CLA 里用浮点比较更省时间与空间
② 定点标度必须显式写出：Q11 → ×(1/2048)；Q10 → ×(1/1024)；标幺换算按基准（示例：4000mV 直流对应 1.0pu）
 CLAVar.f32KVinvDc = (float32)CPUtoCLAVar.i16KVinvDc * f32K1Div2048Cnst; // Q11
 CLAVar.f32V3rdKp = 5000 * f32K1Div1024Cnst; // 3 次谐波 Kp
③ 时间戳可借 ePWM 计数器：cla_time_start = EPWM_TIMER_BASE.TBCTR（条件编译 CLA_TIMING），
 与 CPU 侧 ReadCpuTimer0Counter() 同为"数周期"测法（第37章 37.9）
④ 软件 trace 与 CPU 侧同构：CLA_RUN_FUNCTION 取 0x0001 / 0x0004 ...，
 保留 CLA_RUN_PREVIOUSFUNCTION 记录上一段——卡死时看这两个变量即可定位到具体段落
```

> [!IMPORTANT]
> 与本书代码的映射：第31章 31.11 给出"哪些代码从 CPU 搬到 CLA"的判据（高频率、无阻塞、无通信、有确定 WCET），本节给出"搬过去之后怎么写"。两份约定合起来构成一个可执行的分工表：CPU 侧做锁相、状态机、保护判定、通信（每 2 周期或更慢），CLA 侧做采样读取、相位角、双环、谐波补偿、调制（每周期）。

> [!CAUTION]
> 失败案例复盘（忘记清标志）：把双环搬进 CLA 后出现"每个载波周期负载电流跳两次"的现象：CLA 任务由 ADCINT1 触发，而任务末漏了清 ADCINT1，导致任务在同一采样点被重复触发、双环在一周期内算两次（第二次用的是同一组采样值，等效把积分增益翻倍）。补上AdcaRegs.ADCINTFLGCLR.bit.ADCINT1 = 1后消失。结论：CLA 与 C28x 的中断标志语义不同——C28x 的 ISR 由硬件/向量入口自动清，CLA 任务必须手动清，这条写在 CLA 手册里，但只会在"结果对不上账"时才被想起。
