**本章要解决的问题：** 把"能控"升级为"**任何工况下都能安全地控**"。核心是三层保护路径（硬件 TZ、软件快环、慢环决策）、保护矩阵的定值来源，以及 黑匣子 证据链。

### 36.1 三层保护路径与时间预算

| 层 | 实现 | 响应时间 | 适用 |
| --- | --- | --- | --- |
| 第一层：硬件 | CMPSS + X-BAR → TZ 强制封波 | ≤1~2 µs | 过流、直通、母线过压 |
| 第二层：软件快环 | ISR 内比较 + 去抖（第9章） | 1~3 拍（56~167 µs） | 过流/不平衡/直流分量 |
| 第三层：慢环决策 | 1ms 任务状态机（第34章） | 10~100 ms | 过载降额、温度、绝缘、电池异常 |

> [!IMPORTANT]
> 分工原则：会造成器件损坏的（过流、直通、母线过压）必须走第一层硬件；会损坏负载或影响供电质量的（不平衡、直流分量、THDu 超限）走第二层；需要"思考"的（降额、切旁路、关机）走第三层。不能把所有保护都写成软件判断——软件跑飞时硬件是唯一防线。

### 36.2 算例 36-1：过流保护定值与时间预算

```text
器件：650V/100A SiC MOSFET，额定 76A（rms）、峰值 107.5A、非线性负载峰值 228A
  ① 硬件 TZ 阈值：取 2.5 倍额定峰值 = 270A（避开 CF=3 的正常工况 228A，留 18% 余量）
     响应 ≤2µs → 器件在 2µs 内承受 270A（远低于其 10µs 短路耐受 ~500A）✓
  ② 软件快环：1.8 倍额定峰值 = 194A，去抖 3 拍 → 动作时间 167µs（3×55.6µs，18kHz 载波口径）
     用途：把"持续过流"在硬件动作前先降额/切除（减少 TZ 频繁动作）
  ③ 反时限（I²t）：软件实现，用于 125% 过载 ≥10min 的规范要求（验收表 C 组）
     t = K/(I² − I_rated²)，取 I = 1.25×76 = 95A → 要求 t ≥ 600s
     → K ≥ 600×(95² − 76²) = 600×(9025−5776) = 600×3249 = 1.95e6
       （I 单位 A、t 单位 s；实现时换算成定点或 float 并限幅）
     校验 150% 时：t = 1.95e6/(114² − 76²) = 1.95e6/7220 = 270 s（4.5min，合理）
```

### 36.3 算例 36-2：保护定值的来源（每个数都要能追溯）

| 保护项 | 定值 | 来源 |
| --- | --- | --- |
| 过载能力 | 125% ≥10min | 验收表 C 组（过载能力） |
| 母线过压 | 1.15 倍额定（805V） | 器件耐压 650V×2 = 1300V 母线口径 + 20% 动态余量 |
| 绝缘 | >2MΩ 告警 | 验收表 G 组（绝缘监测） |
| 漏电流 | ≤3.5mA | 验收表 G 组（漏电流保护） |
| 耐压 | 2000VAC/1min | 验收表 G 组（GB 7260.1） |
| 温度 | 散热器 85℃ 降额、95℃ 停机 | 器件 Tj_max 150℃ 反推（第46章） |
| 直流分量 | ≤0.5%，>2% 停机 | 第28章 28-4 与变压器饱和风险 |

### 36.4 算例 36-3：故障处理策略（"降额优先"原则）

```text
故障分级与动作（避免"一有异常就停机"）：
  A 级（器件危险）：过流/直通/母线过压 → 立即封波 + 切旁路（≤1ms）+ 记录
  B 级（影响供电质量）：不平衡超限、直流分量超限、THDu 超限 → 降额 20%，10s 内不恢复再切旁路
  C 级（可容忍）：温度偏高、风扇故障、电池通信中断 → 告警 + 记录，连续运行（电池异常时转旁路）
  D 级（外部）：电网频率越限、电网谐波超限 → 按第34章状态机转电池/旁路

为什么要分级：统计上 60% 以上的"停机"来自 B/C 级异常（可通过降额继续供电）。
              UPS 的价值是"不断电"，能降额就不停。
```

### 36.5 代码：保护矩阵与黑匣子

```c
/* ---------- protect.c ---------- */
#define PROT_TZ_OC_A      270.0f      /* 硬件 TZ 过流阈值（36-2 ①） */
#define PROT_SW_OC_A      194.0f      /* 软件快环阈值（36-2 ②） */
#define PROT_I2T_K        1.95e6f     /* 反时限常数（36-2 ③） */
#define PROT_VBUS_OV_V    805.0f      /* 母线过压（36-3） */
#define PROT_OC_DEBOUNCE  3u          /* 连续 3 拍（第9章） */

/* 故障码（按级分类，日志与遥测共用） */
#define PROT_F_TZ_OC      (1u<<0)      /* A 级 */
#define PROT_F_VBUS_OV    (1u<<1)      /* A 级 */
#define PROT_F_ILLEGAL    (1u<<2)      /* A 级：非法门极组合（第8章） */
#define PROT_F_UNBAL      (1u<<8)      /* B 级 */
#define PROT_F_DC_LEVEL   (1u<<9)      /* B 级 */
#define PROT_F_TEMP_HI    (1u<<16)     /* C 级 */
#define PROT_F_BMS_COMM   (1u<<17)     /* C 级 */
#define PROT_F_GRID_RANGE (1u<<24)     /* D 级 */

static uint8_t oc_cnt;

/* TZ 中断：硬件已封波，这里只做"记录 + 决策"（不要在 ISR 里做复杂逻辑） */
__interrupt void tz_isr(void)
{
    g_prot.fault |= PROT_F_TZ_OC;
    pwm_force_safe_level();
    EPWM_clearTripZoneFlag(EPWM_ALL, EPWM_TZ_FLAG_OST);
    log_fault_snapshot(PROT_F_TZ_OC);            /* 记录故障前后 N 拍波形 */
    Interrupt_clearACKGroup(ISR_TZ);
}

/* 软件快环（在控制 ISR 内，只做判断与置位） */
void prot_fast_check(float i_pk, float v_bus)
{
    if (i_pk > PROT_SW_OC_A) { if (++oc_cnt >= PROT_OC_DEBOUNCE) g_prot.fault |= PROT_F_TZ_OC; }
    else                     { oc_cnt = 0u; }
    if (v_bus > PROT_VBUS_OV_V) g_prot.fault |= PROT_F_VBUS_OV;
}

/* 慢环决策（1ms）：按级处理，能降额就不停机 */
void task_prot_decide(void)
{
    const uint32_t f = g_prot.fault;
    if (f & 0xFFu) {                 /* A 级：立即切旁路 */
        sys_request(SYS_BYPASS);  return;
    }
    if (f & 0xFF00u) {               /* B 级：先降额 20% */
        static uint16_t t_b = 0;
        derate_set(0.8f);
        if (++t_b > 10000u) sys_request(SYS_BYPASS);     /* 10s 未恢复才切 */
        return;
    }
    if (f >> 16) {                   /* C/D 级：告警 + 记录 */
        log_fault_event(EV_WARN, (uint16_t)f);
    }
}

/* 反时限（I²t）累计：用于 125% ≥10min 的规范要求 */
uint8_t prot_i2t_accumulate(float i_rms, float dt_s)
{
    static float acc = 0.0f;
    const float in = 76.0f;
    if (i_rms <= in) { if (acc > 0.0f) acc -= 2.0f*dt_s; return 0u; }
    acc += (i_rms*i_rms - in*in) * dt_s;               /* 累加"热账" */
    if (acc > PROT_I2T_K) { g_prot.fault |= PROT_F_TZ_OC; return 1u; }
    return 0u;
}
```

### 36.7 失败案例复盘：只做了软件过流判断，MCU 复位瞬间炸管

> [!CAUTION]
> 现象：负载短路试验中逆变器炸管，事后日志显示"过流发生"但没有任何保护动作记录。定位路径：①看日志（故障时刻只有一条"过流"记录，无 TZ 事件）→ ②查配置（CMPSS 未接到 TZ，过流只做了软件判断）→ ③复盘时间线（短路电流在 3µs 内升到 600A，而软件判断要 55.6µs，期间 MCU 还在处理中断/记录）→ ④改接 CMPSS→TZ 后通过短路试验。根因：把"器件级保护"交给软件；软件响应时间比器件损坏时间慢 20 倍以上。预防措施：①凡"会造成器件损坏"的保护一律走硬件路径（CMPSS→X-BAR→TZ），并在上电自检里验证通路（触发一次 TZ 看是否封波）；②软件保护只做"记录与决策"；③把"TZ 通路自检"列为上电必测项（本课程列入 LAB5）。

### 36.10 补充：逐波限流、打嗝/锁死与 DESAT 软关断（含参考代码对照）

三层保护（36.1）解决"谁来动作"，还有三个实现层问题必须定清：**过流之后是"每拍限住"还是"关掉等一会儿"**、** 故障后锁死还是自恢复**、** 器件级短路怎么在 5µs 内安全关断**。这三件事在既有工程代码里都有成熟做法，本节给出定量口径与对照。

#### ① 逐波限流（cycle-by-cycle limit）

```text
动作：每拍比较瞬时电流与阈值，超限则本拍封波（或压到最小脉宽），下一拍重新判断
适用：负载冲击、启动、非线性负载峰值（第32章 CF=3 → 峰值 228A）
参数（本课程口径）：
  阈值 = 1.8×额定峰值 = 194A（与 36-2 的软件快环阈值同值，避免两套定值打架）
  去抖 = 0 拍（逐波的意义就是"本拍就限"）
  退出 = 连续 10 拍低于阈值×0.8 后恢复（滞回防抖）
定量效果：每次封波使该拍有效占空比减少约 30%（触发率 30% 的工况）
  → 输出电流被限制在额定的 70% 附近，同时波形出现低频包络
  → 逐波限流是"保住器件"，不是"保住波形"；必须与 B 级降额（36-4）配合
```

#### ② 打嗝（hiccup）与锁死（latch-off）

```text
打嗝：故障后封波 t_off，间隔 t_hiccup 重试，最多重试 N 次仍故障则转锁死
  参数：t_off = 200ms、t_hiccup = 1s、N = 3 → 占空比 = 200/1200 = 16.7%
  定量校核（为什么打嗝能救命）：
    短路瞬时功率 = 270A × 700V = 189 kW
    占空比 16.7% → 平均 31.6 kW；若 t_off = 100ms 且重试拉长到 2s → 占空比 4.8% → 平均 9.1 kW
  反例（关键）：t_off = 10ms、重试 100ms（占空比 9%）看似更小，但每次事件都要经历
    "短路电流上升到 270A + 关断"的瞬态，单次损耗约 0.25J **按次累积**：
    8 次/秒 × 0.25J = 2J/s → 结温持续上升，实际比"少而长"的打嗝更伤器件
  锁死：A 级故障打嗝 N 次仍复现 → 锁死，需人工/上位机复位（禁止内部自动复位）
  自恢复：B/C 级按 36-4 分级直接恢复，不进入打嗝
判据：打嗝期间结温不上升（按第46章热模型核算），且上游断路器不跳闸
```

#### ③ DESAT 与软关断（器件级短路的最后一环）

```text
DESAT（去饱和检测）：监测开通期间 V_ds，超过阈值说明器件进入线性区（短路）
  阈值 7~9V（略高于额定通态压降 2~3 倍）；消隐时间 t_blind = 1~3µs（避开开通振铃）
  时间预算：DESAT 检测 2µs + 软关断 3µs = 5µs（≤ 器件短路耐受 10µs，与 36-7 复盘同口径）
软关断（two-level turn-off）：先经大电阻慢关断把电压降到约 80%，再快速关断
  数值：L_s = 20nH、di/dt 从 1000A/µs 降到 300A/µs → 杂散电感尖峰从 20V 降到 6V
负压关断：−4~−5V（防 dv/dt 误开通，第47章 SiC 替换经验同）
与片上资源配合：DESAT 属驱动板功能，触发后经 X-BAR 拉低 TZ（36-5 的硬件路径）；
  软件只做记录与分级决策，不在 ISR 里做关断判断
```

### 36.11 补充代码：逐波限流 + 打嗝状态机

```c
/* ---------- prot_hiccup.c：逐波限流与打嗝（对照参考代码的保护分级） ---------- */
#define PH_OC_LIM_A      194.0f      /* 逐波限流阈值（36-2 ②，与软件快环同值） */
#define PH_OC_HYST       0.80f       /* 退出滞回 0.8（36-10 ①） */
#define PH_OFF_MS        200u        /* 封波时间 */
#define PH_RETRY_MS      1000u       /* 重试间隔 */
#define PH_RETRY_MAX     3u          /* 重试上限 → 转锁死 */

typedef enum { PH_OK = 0, PH_LIMITING, PH_OFF, PH_WAIT, PH_LATCHED } ph_state_t;
static ph_state_t g_ph = PH_OK;
static uint32_t g_ph_t;  static uint8_t g_ph_retry;  static uint8_t g_ph_clear_cnt;

/* 在控制 ISR 内调用（每拍）：只做"本拍动作"，不做决策 */
uint8_t prot_cycle_by_cycle(float i_pk)
{
    if (g_ph == PH_LATCHED) return 0u;                    /* 锁死：不给门极 */
    if (fabsf(i_pk) > PH_OC_LIM_A) {
        g_ph = PH_LIMITING;
        g_ph_clear_cnt = 0u;
        return 0u;                                        /* 本拍封波 */
    }
    if (g_ph == PH_LIMITING) {
        if (++g_ph_clear_cnt > 10u) g_ph = PH_OK;         /* 连续 10 拍恢复 → 解除 */
    }
    return 1u;
}

/* 1ms 任务：打嗝与锁死（决策放慢任务） */
void task_prot_hiccup(void)
{
    switch (g_ph) {
    case PH_LIMITING:
        if (++g_ph_t > PH_OFF_MS) { g_ph = PH_OFF; g_ph_t = 0u; pwm_force_safe_level(); }
        break;
    case PH_OFF:
        if (++g_ph_t > PH_OFF_MS) { g_ph = PH_WAIT; g_ph_t = 0u; }
        break;
    case PH_WAIT:
        if (++g_ph_t > PH_RETRY_MS) {
            g_ph_t = 0u;  g_ph_retry++;
            if (g_ph_retry > PH_RETRY_MAX) {
                g_ph = PH_LATCHED;
                g_prot.fault |= PROT_F_LATCHED;
                log_fault_event(EV_HICCUP_LATCH, (uint16_t)g_ph_retry);
            } else {
                g_ph = PH_OK;
                log_fault_event(EV_HICCUP_RETRY, (uint16_t)g_ph_retry);
            }
        }
        break;
    case PH_LATCHED: break;                                /* 等人工/上位机复位 */
    default:         g_ph_t = 0u; break;
    }
}

/* 锁死复位只能来自外部命令（禁止内部自动清除） */
uint8_t prot_hiccup_reset(uint8_t from_command)
{
    if (!from_command) return 1u;
    g_ph = PH_OK;  g_ph_retry = 0u;  g_ph_t = 0u;
    g_prot.fault &= (uint32_t)~PROT_F_LATCHED;
    return 0u;
}
```

> [!CAUTION]
> 失败案例复盘（打嗝周期过短）：某机型短路保护用"10ms 封波 + 100ms 重试"，实验室通过，现场反复短路 8 次后炸管。核算：每次事件都经历"短路电流升到 270A + 关断"的瞬态，单次损耗约 0.25J，8 次/秒连续 3 秒 = 24 次 → 结温累积超过降额线。改为"200ms 封波 + 1s 重试 + 3 次后锁死"后同样试验下结温不上升。打嗝参数不能只看平均功率小，必须按"单次事件损耗 × 事件频率"核算结温。

### 36.12 补充练习

1. **E4** 逐波限流阈值取 1.5 倍额定峰值（161A）：算 CF=3 的非线性负载（峰值 228A）下的触发率与输出能力损失；给出"阈值与负载峰值系数"的匹配规则。
2. **E5** 用 36-10 ② 的模型算"t_off = 50ms、t_hiccup = 500ms"的打嗝占空比、平均功率与单次事件损耗（按 0.25J/次），判断散热器是否承受得住。
3. **E6** 对照 `md380_foc_float.h` 的"大转矩切纯 P"做法，为本书逆变器设计"过载时切换控制结构"方案（何时切、切什么、怎么恢复），并给出与 36-4 分级策略的接口。（参考答案见 [练习参考答案](/posts/power/courses/ups-pcs-dsp/docs/answers/)）
