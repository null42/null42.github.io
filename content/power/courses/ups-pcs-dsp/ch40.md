**本章要解决的问题：** 通信是"辅助任务"，但它的故障会拖垮主控制。三个算例：报文预算（总线能不能装下）、数据一致性（读到的参数是不是同一时刻的）、通信故障降级（丢通信还能不能跑）。

### 40.1 链路与周期（本课程口径）

| 链路 | 速率 | 用途 | 周期要求 |
| --- | --- | --- | --- |
| CAN（模块间） | 1 Mbps | 均流、状态、SOE | ≤10ms（第38章均流前提） |
| CAN（监控） | 500 kbps | 遥测、告警 | 100ms~1s |
| RS485/Modbus | 19.2~115 kbps | 对接楼宇/动环 | 1s |
| 以太网/SNMP | 100 Mbps | 上位机、云平台 | 1~10s |

### 40.2 算例 40-1：CAN 总线负载率预算

```text
1 Mbps CAN，标准帧 11 位 ID、8 字节数据：
 单帧位数 ≈ 44（帧头/仲裁/控制）+ 64（数据）+ 20（CRC/应答/间隔）= 128 位
 单帧传输时间 = 128/1e6 = 128 µs

 4 模块，每模块每 10ms 广播 1 帧（电流/状态）：帧率 = 4×100 = 400 帧/s
 总线占用 = 400×128µs = 51.2 ms/s → 负载率 5.1% （安全线 ≤30%）
 再加监控侧 20 帧/s/模块（80 帧/s）→ 480 帧/s → 6.1% 
 事件帧（故障/切换）峰值：20 帧/100ms = 200 帧/s → 瞬时 2.6%（叠加后 8.7%）
 判据：稳态 ≤30%、瞬时峰值 ≤60%（留仲裁冲突与重发余量）
```

### 40.3 算例 40-2：数据一致性——为什么要双缓冲

```text
错误做法：上位机直接读控制 ISR 正在写的结构体
 现象：读到"半新半旧"数据（如功率是新值、电流是旧值）→ 上位机算出功率因数 2.3（不可能值）
 概率估算：ISR 每 55.6µs 写入一次，写入耗时约 5µs → 命中概率 = 5/55.6 ≈ 9%
 单次读 12 个变量 → 至少一个不一致的概率 ≈ 1 − (1−0.09)^12 = 68% 

正确做法（双缓冲 + 序号）：
 写侧（ISR）：写 buffer_b → 序号 ++ → 指针切换（原子操作 1 条指令）
 读侧（通信任务）：读序号 → 读 buffer_a → 再读序号，两次相同才使用
 代价：RAM 翻倍（遥测结构约 200 B → 400 B），CPU 开销 <10 周期 
```

### 40.4 算例 40-3：通信故障降级

```text
场景：并机系统 CAN 断线
 ① 模块间均流帧丢失 >50ms → 退化到纯下垂（第38章）：环流度从 2% 升到 3~5%，仍达标 
 ② 监控链路丢失 → 继续按本地设定运行，缓存最近 5min 数据（断线续传）
 ③ 若为"主从"结构且主机失联 → 从机按"最后指令 + 下垂"运行，并置告警；主机恢复后重新同步

 超时定值的依据：均流修正的时间常数 ≈ 10ms×5 = 50ms → 超过 50ms 无新数据即视为失效
 判据：任意一条通信链路断开 1min，输出指标（THDu ≤1%、不平衡度 ≤5%、环流度 ≤5%）保持不变
```

### 40.5 代码：双缓冲遥测与降级

```c
/* ---------- comm.c ---------- */
typedef struct {
 float v_out, i_out, p_out, f_out; /* 遥测快照 */
 float v_bus, i_batt, temp_hs, thdu;
 uint16_t fault, mode; uint32_t ms;
} telem_t;

static telem_t g_tbuf[2];
static volatile uint8_t g_tidx; /* ISR 写侧指针 */
static volatile uint32_t g_tseq; /* 序号（写侧递增） */

/* ISR 侧（1ms 任务里也可）：写"备"缓冲，然后原子切换 */
void telem_publish(void)
{
 telem_t *b = &g_tbuf[g_tidx ^ 1u];
 b->v_out = inv_v_rms(); b->i_out = inv_output_current_rms();
 b->p_out = p_measured(); b->v_bus = adc_to_volt(g_adc.raw_vbus, &g_adc.cal_vbus);
 b->fault = (uint16_t)g_prot.fault; b->mode = (uint16_t)g_fsm.st;
 b->ms = g_ms_tick;
 g_tidx ^= 1u; /* 原子切换（单字节写） */
 g_tseq++;
}

/* 通信任务侧：带序号校验的读 */
uint8_t telem_read(telem_t *out)
{
 const uint32_t s1 = g_tseq;
 const uint8_t i1 = g_tidx;
 *out = g_tbuf[i1];
 return (g_tseq == s1); /* 序号未变 → 数据一致 */
}

/* 通信故障降级：由 100ms 任务判定 */
void task_comm_degrade(void)
{
 if (g_comm.last_rx_ms_gap > 50u) { g_state.comm_lost = 1u; par_degrade_to_droop(); }
 else { g_state.comm_lost = 0u; }
 if (g_comm.monitor_lost) comm_cache_store(&g_telem_latest); /* 断线续传缓存 */
}
```

### 40.6 上机核对（LAB5）

| 步骤 | 该看到什么 | 判据 |
| --- | --- | --- |
| 总线负载率 | CAN 分析仪统计 | 稳态 ≤30%、峰值 ≤60%（40-2） |
| 遥测一致性 | 连续读 10 万次，检查物理关系 | 无"功率因数>1"类异常（40-3） |
| 拔 CAN 线 | 并机运行与环流度 | 1min 内指标不变、有告警 |
| 通信风暴注入 | ISR 时长 | 最大时长不增加（通信不进 ISR） |
| 告警上报延迟 | 故障到上位机显示 | ≤1s（SOE 时间戳误差 ≤10ms） |

### 40.7 失败案例复盘：监控轮询直接读 ISR 变量，上位机频繁报"功率因数异常"

> [!CAUTION]
> 现象：上位机偶发报"功率因数 2.1"、"效率 120%"等逻辑不可能值，告警刷屏。定位路径：①复现（读 10 万次，异常率约 68%，与 40-3 的估算吻合）→ ②确认直接读取 ISR 正在更新的结构体 → ③改双缓冲 + 序号校验后异常率 0。根因：多字节数据跨 ISR 边界读取，得到"时间不一致"的组合。预防措施：①所有跨上下文数据必须双缓冲/序号校验；②上位机侧加"物理合理性检查"（PF ≤1、效率 ≤100%），异常值丢弃并计数；③把"遥测一致性"列为通信功能的验收项。

### 40.8 验收量化单

| 项目 | 判据 | 测量方式 | 关联实验 |
| --- | --- | --- | --- |
| 总线负载 | ≤30% / 峰值 ≤60% | CAN 分析仪 | LAB5 |
| 数据一致性 | 10 万次读无异常 | 一致性检查 | LAB5 |
| 通信降级 | 断线 1min 指标不变 | 断线测试 | LAB5 |
| 告警时延 | ≤1s，时间戳误差 ≤10ms | SOE 校验 | LAB5 |
| 不阻塞控制 | 通信不进入 ISR；任务超时有看门狗 | 代码审查 + 打点 | LAB0 |
