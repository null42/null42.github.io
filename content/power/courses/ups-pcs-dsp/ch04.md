**本章要解决的问题：** 让控制环**按时、不丢拍、不抖动**。中断写错清标志顺序会丢中断，优先级排错会让保护迟到，重活放进 ISR 会把采样时刻搅乱。本章给出三级结构、ISR 三件套、周期与抖动两个量化预算，以及一份"中断不来/只来一次"的排查决策树。

### 4.1 GPIO：先定安全态，再谈功能

| 配置项 | 要点 | 典型坑 |
| --- | --- | --- |
| 复用（MUX） | 按"外设 ↔ 引脚"映射表逐条核对（不同封装映射不同） | 同一引脚配两次 → 外设行为随机 |
| 方向（DIR） | PWM/告警输出为输出；按键/故障输入为输入 | PWM 脚配成输入 → 桥臂失控 |
| 上拉/下拉 | 未用引脚给确定电平；通信接收脚上拉 | 悬空输入被噪声翻转 → 误触发中断 |
| 输入限定 | 外部故障信号开启输入滤波（采样窗） | 无滤波 → 一次尖峰就报故障 |
| 上电安全态 | 使能 PWM 输出**之前** 把栅极驱到关断 | 漏掉 → 上电瞬间直通 |

```text
// 上电顺序的关键三行：先安全态，再配外设，最后使能输出
GPIO_setDirectionMode(PIN_PWM_UH, GPIO_DIR_MODE_OUT);   // ① 方向
GPIO_writePin(PIN_PWM_UH, 0);                            // ② 先写关断电平（低有效驱动时为 0）
EPWM_disableOutput(EPWM_A);                              // ③ 输出关闭，配置期间不动作
EPWM_configDeadBand(EPWM_A, 2200e-9f, ...);              // ④ 配死区
EPWM_enableTripZone(EPWM_A);                             // ⑤ 先上保护
EPWM_enableOutput(EPWM_A);                               // ⑥ 最后才允许输出
```

> [!IMPORTANT]
> 引脚"三查"：①查复用表（该脚能不能做这个外设）；②查冲突（是否被别的外设/调试口占用）；③查上电态（复位到初始化之间输出什么电平）。三查在纸面完成，成本最低。

### 4.2 中断三级结构（含寄存器名）

```text
外设事件（ePWM 周期、ADC 完成、CMPSS 跳闸…）
   │ ① 外设级：该外设自己的中断使能位 + 标志位
   ▼
ePIE：PIEIFR（组内标志）/ PIEIER（组内使能）/ PIEACK（组应答）
   │ ② 组级：分组 × 通道映射到 CPU 中断线
   ▼
CPU：IFR（中断标志）/ IER（中断使能）/ INTM（全局屏蔽）
   │ ③ 核级：三级都放开才进 ISR
   ▼
ISR：清外设标志 → 清 PIE 组标志 → 写 PIEACK 应答本组
```

> [!WARNING]
> ePIE 的分组数、每向量字数与向量表基址随型号不同，必须以《TMS320F2807x TRM (Rev. H)》中断章节核对后写入代码（按老型号的"12 组×8"理解会漏中断）。本课程只讲机制，不写未核实的数字。

### 4.3 ISR 三件套：顺序错了会怎样

```c
__interrupt void isr_control(void)
{
    const float ia = ADC_readPhaseA();      // ① 先取本拍数据（防被下一拍覆盖）
    const float ib = ADC_readPhaseB();
    const float ic = ADC_readPhaseC();

    ctrl_step(ia, ib, ic);                  // ② 保护扫描→控制算法→PWM 影子写入

    ADC_clearIntFlag(ADC_BASE);             // ③ 清外设标志
    Interrupt_clearACKGroup(INT_CTRL);      // ④ 应答 PIE 组（允许本组再次响应）
}
```

| 写错 | 现象 | 机理 |
| --- | --- | --- |
| 先应答、后清外设标志 | 中断只进一次，之后"再也不来"或反复进入饿死主循环 | 应答时外设标志仍置位，硬件状态机不满足再次触发条件 |
| 漏 PIEACK 应答 | 本组后续中断全部被挡住 | 应答是"允许本组再次响应"的总开关 |
| 在 ISR 里做长活 | 周期抖动、采样时刻漂移、偶发丢拍 | 下一拍被推迟，采样点不再与载波对齐（第5章） |

### 4.4 ISR 只做五件事 + 周期预算

**采样 → 保护扫描 → 控制算法 → PWM 更新 → 清标志应答。**

| 可以放 | 严禁放 |
| --- | --- |
| 四则运算、查表、饱和限幅、一次 `volatile` 写缓冲 | 除法（除非 TMU）、三角函数慢实现、printf、Flash 写、等锁存、大循环 |

> [!IMPORTANT]
> 周期预算（与第2章算例 2-2 同口径，控制中断 9kHz（奇偶双拍），周期 111.1µs = 13,333 周期/拍）：平均 2020 周期（15.2%）、最坏 2600 周期（19.5%）→ 判据"平均 ≤40%、最坏 ≤50%"。实测用 GPIO 打点：进入 ISR 拉高、退出拉低，示波器直接读 μs。

### 4.5 算例 4-1：ISR 周期预算与"要不要拆任务"

```text
已知（与第2章算例 2-2 同口径）：控制中断 9kHz（每 2 载波一次，奇偶双拍）→ 周期 111.1µs → 120MHz 下 13,333 周期/拍

各段周期（预算值）：
  采样读取与换算（3 相电流 + 3 电压）............  200
  保护扫描......................................   80
  PLL / SOGI...................................  400
  电流环（Clarke/Park + 2×PI + 解耦）...........  300
  电压环（2×PR + 限幅）.........................  250
  谐波补偿（5/7 次 PR）..........................  500
  SVPWM + 占空比计算............................  250
  PWM 影子写入 + 三件套应答......................   40
  ──────────────────────────────────────────
  平均合计 .................................... 2020 → 占用率 2020/13,333 = 15.2%
  最坏（限幅/故障分支全开）.................... 2600 → 2600/13,333 = 19.5%

判据：平均 ≤40%、最坏 ≤50% → 本预算合格
敏感度：若再加入 11/13 次谐波补偿（+600 周期）：
  最坏 3200 → 24.0%（3200/13,333），仍合格，余量还有 26 个百分点
  若还想加 SDFM 滤波或 CLA 交互开销 → 必须搬任务或降次
```

### 4.6 算例 4-2：中断延迟预算（保护为什么必须走硬件）

```text
从"电流越限"到"PWM 真正消失"，两条路径对比：

路径 A：硬件（CMPSS → X-BAR → ePWM TZ）
  比较器传播延迟 + X-BAR 路由 + TZ 生效       ≈ 数十~数百 ns
  → 判据 <1µs（LAB5）

路径 B：软件（ADC 采样 → ISR 读值 → 判断 → 写 TZ/强制电平）
  ADC 采样与转换（12bit）................ ≈ 1µs 量级
  等到下一拍中断（最坏一整拍）............ 55.6µs
  ISR 内判断与响应........................ 约 0.1~0.5µs
  ────────────────────────────────────
  最坏 ≈ 57µs（1 + 55.6 + 0.5）→ 以 di/dt = 0.267 A/µs 计，电流会多涨 57 × 0.267 ≈ 15.2 A

结论：软件路径的响应时间由"采样+一拍"决定，量级是几十微秒；
      保护必须走硬件路径（一次性跳闸），软件只做"事后记录与恢复判断"。
```

### 4.7 算例 4-3：抖动值多少钱（采样时刻抖动的物理后果）

```text
电感电流斜率： di/dt = V_dc / L = 400V / 1.5mH = 0.267 A/µs

若采样时刻抖动 ε = 1µs（被高优先级中断抢占所致）：
  电流采样误差 = 0.267 A/µs × 1µs = 0.267 A
  对 2kW/220V 系统（额定 9.1A）占比 = 0.267 / 9.1 = 2.9%

若抖动到 5µs：误差 1.33A = 14.6% 额定  → 电流环会把这份"假误差"当真去调，
                                          表现为轻载发抖、重载偶发过流误报
```

| 抖动来源 | 量级 | 对策 |
| --- | --- | --- |
| 高优先级 ISR 抢占 | 取决于其最长执行时间 | 缩短高优先级 ISR（只置标志）；把重活放慢任务 |
| ISR 内分支不定 | 数十周期 | 控制路径去分支化（限幅用条件赋值） |
| 软件启动采样 | ISR 进入时刻的抖动全部转移给采样 | 改由 ePWM 硬件事件触发 SOC（第5章） |

> [!WARNING]
> 结论：抖动不是"读数的噪声"，它会直接变成电流误差。判据：采样时刻抖动 <2% 周期（18kHz 下 ≤1.11µs，即 2%×55.6µs）→ 电流误差 <0.30A（3.3% 额定）。

### 4.8 优先级分配

| 优先级 | 中断源 | 做什么 | 预算 |
| --- | --- | --- | --- |
| 最高（硬件） | CMPSS → ePWM TZ | 封 PWM，不经软件 | <1µs（第36章） |
| 高 | ePWM 周期（控制中断） | 采样→控制→PWM 更新 | 最坏 ≤50% 周期 |
| 中 | 外部故障 / 通信接收 | 只置标志与入队 | 微秒级 |
| 低 | 1ms / 10ms 定时 | 遥测、通信、保存、状态机 | 不得阻塞控制中断 |

> [!TIP]
> 实践建议：不要让控制中断可被嵌套中断打断同一组资源；宁可让高优先级中断"只置标志、立刻退出"，把处理留给控制中断的下一次执行——这样抖动可控。

### 4.9 排查决策树：中断不来 / 只来一次

| 现象 | 查这里（按顺序） | 验证动作 |
| --- | --- | --- |
| 完全不来 | ① 外设标志置位了吗 → ② 外设中断使能 → ③ PIEIER 该通道 → ④ IER 该位 → ⑤ INTM | 逐级读寄存器，从外设往 CPU 倒推 |
| 只来一次 | ① 外设标志是否清除 → ② PIEACK 是否应答 | 改清标志顺序；在 ISR 入口点亮 GPIO 看次数 |
| 偶发丢拍 | ① 是否有更长的高优先级 ISR → ② 是否在 ISR 内长时间关中断 → ③ 是否有 1ms 任务与中断争用 | GPIO 打点统计周期缺口 |
| 周期抖动大 | ① 高优先级 ISR 长度 → ② ISR 内分支 → ③ 采样由软件启动 | 示波器测进入时刻分布 |

### 4.10 上机核对（LAB0/LAB5）

| 步骤 | 该看到什么 | 判据 |
| --- | --- | --- |
| GPIO 打点测周期 | 方波周期 55.6µs，脉宽 = ISR 执行时间 | 周期抖动 <2%（≤1.11µs） |
| 最坏路径打点 | 注入限幅/故障分支后测最长脉宽 | ≤27.8µs（50%×55.6µs） |
| 进入次数核对 | ISR 计数与 ePWM 周期数一致 | 10 分钟无丢拍 |
| 断开软件验证 TZ | 越限信号 → PWM 立即消失 | 延迟 <1µs |

### 4.11 失败案例复盘：漏一次 PIEACK，通信整段消失

> [!CAUTION]
> 现象：加入"通信接收中断"后，运行 1 分钟上下位机通信断流，但控制与保护都正常。定位路径：①查通信中断是否还在触发（GPIO 打点：不触发了）→ ②读 PIE 组标志（置位但未应答）→ ③查通信 ISR 代码（结尾只清了外设标志，漏了组应答）→ ④补上应答后恢复。根因：该组第一次响应后未应答，整组被硬件挡住；控制中断在另一组，所以"只有通信消失"这个现象具有强误导性。预防措施：①ISR 模板统一为"三件套 + 应答"，评审时逐个数；②每个组的 ISR 都必须有一条"应答"语句；③把"每组的应答"写进代码检查单。
