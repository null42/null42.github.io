**本章要解决的问题：** 让工程**安全地** 跑、波形**不停机** 看、上电不漏步。功率电子调试与普通单片机最大的差别是：一次断点、一次顺序错，代价是炸管。本章给出工程结构与分区、**一次真实事故的时间线**、Graph 波形配置与观测窗口算例、上电防漏清单、以及能提前抓出离散化错误的"四方对拍"流程。

### 3.1 工程结构与文件职责

```c
ups_ctrl/
├── source/
│   ├── main.c        // 上电初始化序列 + 主循环（低优先级）
│   ├── isr.c         // 控制中断：采样→保护扫描→控制算法→PWM 更新→应答
│   ├── task.c        // 1ms/10ms 慢任务队列：遥测、通信、参数保存、状态机
│   ├── protect.c     // 保护矩阵、故障码、黑匣子日志
│   └── comm.c        // Modbus/CAN 协议栈
├── include/
│   ├── param_table.h // 所有可调参数集中定义（+CRC16）
│   └── global.h      // 共享变量（volatile）
└── cmd/
    ├── ram_lnk.cmd   // RAM 调试：波形缓冲、日志段放 RAM
    └── flash_lnk.cmd // Flash 烧录：注意初始化段与运行段分离
```

| 文件 | 职责 | 关键函数（签名示例） | 禁止 |
| --- | --- | --- | --- |
| main.c | 时钟/外设/参数/状态机初值 | `void app_init(void);` | 放控制算法 |
| isr.c | 全部硬实时动作 | `void ctrl_step(float ia,float ib,float ic);` | 放 printf/Flash 写/等锁存 |
| task.c | 非实时但必须做的事 | `void task_1ms(void); void task_10ms(void);` | 长时间阻塞 |
| protect.c | 阈值判定、锁存、去抖、日志 | `uint16_t protect_scan(void);` | 直接操作 PWM 输出（用 TZ） |

> [!IMPORTANT]
> 分区纪律：波形缓冲与黑匣子日志在 RAM 调试工程里放在 RAM；Flash 运行时它们仍在 RAM（由链接文件分配），不要为了"省 RAM"把日志放 Flash——Flash 写是毫秒级操作，且寿命有限（第37章）。

### 3.2 断点安全铁律

| 场景 | 允许 | 禁止 |
| --- | --- | --- |
| 纯算法（母线未上电） | 断点、单步、变量观察 | — |
| 带功率级闭环运行 | Graph 波形、日志、GPIO 打点、事件捕获 | 任何断点/单步；运行中热改保护阈值后立即带载 |
| 保护动作验证 | 先低压小电流验逻辑，再上真实电流 | 在保护路径上设断点 |

#### 事故时间线：一次 ISR 断点的代价

> [!CAUTION]
> 条件：母线 400V、负载 2kW、开关频率 18kHz、电感 1.5mH。动作：在电流环 ISR 里下断点，试图观察电流给定。时间线（实测复盘）：| 时刻 | 发生了什么 | 量级 || --- | --- | --- || t=0 | 断点命中，CPU 停；PWM 保持最后一次占空比不变 | — || t=0.2ms | 电感电流按 di/dt = Vdc/L 继续上升 | 0.267 A/µs × 200µs ≈ 53A || t=0.5~1ms | 电流超过 IGBT 与电感的设计电流；TZ 硬件保护本应动作，但软件路径被冻结、故障状态未被记录 | — || t≈2ms | 器件过流失效（或 TZ 动作但反复触发） | — |根因：把"观察手段"用在了唯一不能停的地方。正确做法：用 3.3 的 Graph 环形缓冲——它不停 CPU，只往内存写数。预防措施：①工程里把"带功率级运行"写进调试检查表，断点前先做"母线是否带电"确认；②任何异常卡顿后，先断输入、验放电再动手；③保护路径必须能做到"软件冻结也能封 PWM"（第36章 TZ）。

### 3.3 Graph 环形缓冲：不停机的观测手段

```c
#define SCOPE_LEN 1024                      // 2 的幂：取模变位与
typedef struct { float v[SCOPE_LEN]; volatile uint16_t head; } scope_t;
scope_t sc_iref, sc_ifb, sc_vout, sc_vbus;  // 4 通道即可覆盖大多数排查

static inline void scope_push(scope_t *s, float x) {
    s->v[s->head & (SCOPE_LEN - 1)] = x;    // 只赋值：零分支、零除法
    s->head++;
}

// 控制 ISR 内（末尾统一入队，避免散落在算法中间）
scope_push(&sc_iref, iref);
scope_push(&sc_ifb,  ifb);
```

#### 算例 3-1：观测窗口够不够看

```text
观测时长 T_obs = N / f_sw
  若 N = 1024、f_sw = 18kHz → T_obs = 1024/18000 = 56.9 ms
  50Hz 系统：56.9ms ≈ 2.8 个工频周期          → 看稳态波形够
  要观察 5 次谐波（250Hz，周期 4ms）：56.9ms × 250Hz = 14.2 个周期 → 够
  要看开机过程（数百 ms）：N 需 ≥ 16k×0.5s/… → 改用"抽点记录"或降低记录频率
```

#### 算例 3-2：缓冲占多少内存

```text
内存 = N × 4B × 通道数
  4 通道 × 1024 点 × 4B = 16 KB          → 与第2章算例 2-3 的 16KB 一致
  若扩到 8 通道 × 2048 点 = 64 KB        → 已占 RAM(100KB) 的 64%，需重新评估
```

| 现象 | 常见原因 | 验证动作 |
| --- | --- | --- |
| 波形是一条直线 | 变量被优化掉、或缓冲未写入；断点没跑到 | 加 `volatile`；用 `head` 是否递增判断是否执行 |
| 波形混叠成低频 | 记录频率低于信号频率（如用 1ms 慢任务记录 18kHz 的量） | 记录点必须来自控制 ISR，不是慢任务 |
| 周期性尖刺 | 高优先级中断抢占导致采样时刻抖动 | 见第4章抖动预算：1µs 抖动 → 0.267A 采样误差 |

### 3.4 上电初始化防漏清单（每条附症状与检测法）

| # | 动作 | 漏掉的症状 | 检测方法 |
| --- | --- | --- | --- |
| 1 | 时钟与 PLL 配置、外设时钟使能 | 外设寄存器写入无效，表现为"配置没生效" | 回读寄存器 + GPIO 翻转测频 |
| 2 | 看门狗先关或先喂 | 初始化超时被复位，表现为"随机跑飞" | 读复位原因寄存器 |
| 3 | GPIO 先置安全电平（栅极关断） | 上电瞬间直通 | 低压上电看母线电流尖峰 |
| 4 | TZ/跳闸源先配好，再使能 PWM | 保护形同虚设 | 注入越限信号测封波延迟 |
| 5 | ADC 校准与通道自检 | 采样链断线却"读到数" | 已知电压逐通道比对 |
| 6 | 参数加载 + CRC 校验 | 参数区损坏导致行为异常且无提示 | 故意破坏 CRC 看是否回退默认值 |
| 7 | 预充完成确认后再允许闭环 | 冲击电流触发上级保护（第35章） | 看母线电压斜率与预充电阻温度 |
| 8 | 状态机初值 = 待机，不是运行 | 上电即输出，负载受冲击 | 上电示波器看输出是否立即建立 |

### 3.5 四方对拍：不上功率级也能抓出错误

```text
四份"同一控制律"的实现，两两对拍：
  ① 解析推导（手算/符号）     ② MATLAB/Simulink 模型
  ③ 桌面 C（PC 上跑同一份算法） ④ 目标机（F28075）
```

| 对拍 | 怎么做 | 抓什么错 |
| --- | --- | --- |
| ①↔② | 扫频 Bode 与手算传函叠图（LAB1） | 建模步骤错、忘记 1.5Ts 延迟 |
| ②↔③ | 同一组输入序列，逐拍比对输出（浮点） | 离散化公式错、饱和位置错 |
| ③↔④ | 目标机把输入输出按拍写入缓冲，回灌桌面 C | 类型/定标/优化副作用 |

#### 算例 3-3：离散化方法选错会差多少相位

```text
积分环节在 1.8kHz（= f_sw/10）处的相位误差：
  后向欧拉（1/s → Ts·z/(z−1)）：滞后 ≈ ωTs/2
      = 2π × 1800 × 55.6e-6 / 2 = 0.314 rad = 18.0°
  Tustin（s = (2/Ts)(z−1)/(z+1)）：频率轴映射精确，1.8kHz 处误差 ≈ 0°
      （前提：预畸变穿越频率，见第0章 0.C）

→ 若把控制器用后向欧拉离散，却按 Tustin 的相位预算整定，
   实际 PM 会比设计值少约 18°（45° 目标 → 27°，进入"勉强稳定"区）
```

> [!IMPORTANT]
> 纪律（第0章 0.C）：控制器用 Tustin + 预畸变；被控对象模型用后向欧拉或 ZOH。混用会让"仿真看起来对、实测裕度不够"。

### 3.6 参数与版本管理

```text
参数表布局（Flash 双备份）：
  区 A：参数数组（200 项 × 4B = 800B）+ CRC16
  区 B：同上（备份）
  区 C：标定系数（增益/偏置，见附录 B）+ CRC16
  区 D：出厂默认值（只读）

上电流程：
  读 A → 校验 CRC → 通过则用，否则读 B → 再失败则用 D 并记录故障码
```

| 要点 | 做法 | 理由 |
| --- | --- | --- |
| 写触发策略 | 变化即写 or 定时写（二选一，写进文档） | 频繁写 Flash 会缩短寿命，必须有次数统计 |
| 版本号 | 代码版本 + 参数版本一起打进日志与遥测 | 现场问题定位第一步就是"哪个版本" |
| 回退 | 保留"恢复出厂默认"路径并做验证 | 参数被改乱时能一键复位 |

### 3.7 上机核对（LAB0 第三部分）

| 步骤 | 该看到什么 | 判据 |
| --- | --- | --- |
| RAM/Flash 两套工程运行一致 | 同一占空比下桥臂波形、ADC 读数一致 | 差异 <1% FS |

### 3.8 失败案例复盘：Flash 运行时"波形缓冲把栈压了"

> [!CAUTION]
> 现象：RAM 调试工程一切正常；烧到 Flash 后随机死机，重启后又正常。定位路径：①读复位原因（看门狗）→ ②量主循环执行时间（正常）→ ③看链接 map（发现波形缓冲 16KB + 日志 10KB 与栈区相邻，深调用时压栈越界）→ ④改分区后稳定。根因：RAM 与 Flash 两套链接文件的分区不同（初始化段大小不同），只调试了 RAM 那套。预防措施：①两套链接文件都必须跑"栈深度 + 缓冲占用"检查；②链接 map 里的段边界纳入评审清单；③压栈越界这类问题优先怀疑内存布局，而不是算法。

### 3.11 补充：HRPWM 与载波相移（参考工程实证）

```text
参考工程 ePWM1/2 均使能高分辨率 PWM：
  HRCNFG.bit.EDGMODE = HR_REP（上升沿高分辨率）、HRLOAD = HR_CTR_ZERO_PRD、CTLMODE = HR_CMP、AUTOCONV = 1
  HRPCTL.bit.HRPE = 0（脉宽高分辨率关闭，只用边沿细分）
分辨率：HRPWM 在 60MHz 时基上提供约 150ps 的边沿细分
  占空比分辨率 = 150ps / 55.6µs = 2.7e-6 → 可分辨 1/2.7e-6 ≈ 3.7e5 步 ≈ 18.5 位
  （普通 PWM：1/1667 = 6.0e-4 ≈ 11 位；HRPWM 与 1667 计数分辨率之比约 222 倍，即 2^7.8）
何时需要 HRPWM（本课程口径）：
  ① 低频输出时的小占空比分辨（50Hz 逆变器过零附近）
  ② 并机相位微调（第38章：相位差 0.2° 即产生 14% 环流，HRPWM 把可调步进降到 0.15ns 量级）
  ③ 改善 THDu（边沿抖动降低 → 开关谐波更集中、滤波器更好设计）
代价与注意：需 AUTOCONV 与 SFO 自校准配合；与死区、跳闸的交互必须复核；测量需按 HR 位解析
载波相移（错拍）用 TBPHS + SYNCIN/SYNCOUT 实现，也可用 CMPC/CMPD 标记点——
参考工程即用 CMPC = 1517 / CMPD = 150 标注 2.49µs 的采样触发偏移
```
