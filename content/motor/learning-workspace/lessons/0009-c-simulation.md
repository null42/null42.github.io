从仿真入口索引到数字孪生，系统掌握电机控制仿真全链路。涵盖仿真模式选择、环境搭建、代码映射、绘图分析、emachinery工具及数字孪生前沿技术。

SIM-00

## 仿真入口总索引

核心概念&#9660;

#### 仿真模式分类

电机控制仿真分为**开环验证**（给定角度信号验证算法逻辑）、**闭环仿真**（含观测器的完整FOC链路）、**参数辨识**（从激励响应提取电机参数）和**系统级仿真**（含功率器件、热模型的多物理域耦合）四种模式。

#### KB模块与仿真映射

知识库中每个理论模块都有对应的仿真入口。例如KB-04(FOC算法)对应闭环FOC仿真，KB-05(观测器)对应PLL/SMO仿真，KB-06(电流环)对应PI参数整定仿真。通过总索引可快速定位。

#### 仿真精度层级

**理想模型**：忽略死区、采样延迟、量化误差，用于算法验证。**非理想模型**：含死区、延迟、噪声，接近真实工况。**硬件在环**：真实控制器+虚拟被控对象，最高置信度。

#### 仿真工具链

Python C扩展(emachinery)用于快速验证；Streamlit前端提供交互式参数调整；Simulink用于复杂系统级仿真；C代码仿真用于与嵌入式代码1:1对照。

| KB模块 | 仿真模式 | 推荐工具 | 验证目标 |
| --- | --- | --- | --- |
| KB-04 FOC算法 | 闭环FOC仿真 | emachinery / Simulink | Clarke/Park变换、PI调节、SVPWM |
| KB-05 观测器 | 角度观测仿真 | emachinery (SMO/PLL) | 角度跟踪精度、收敛速度 |
| KB-06 电流环 | PI参数整定仿真 | emachinery / Simulink | 带宽、超调、稳态误差 |
| KB-07 速度环 | 速度环仿真 | emachinery / Simulink | 速度跟踪、抗扰 |
| KB-08 SVPWM | 调制仿真 | C代码仿真 | 扇区判断、占空比计算 |
| KB-03 硬件 | 参数辨识 | emachinery (ID) | Rs/Ls/Flux辨识精度 |

关键原则：仿真先行，实机验证。任何算法改动必须先在仿真中通过，再下载到硬件。仿真置信度取决于模型的非理想因素完整度，理想模型只能验证逻辑正确性。

理想模型只验证了算法逻辑的正确性，但实际系统中存在大量非理想因素会导致算法失效：

1. **PWM死区时间：**导致输出电压畸变，低速时电流交叉畸变严重，PI调节器无法补偿。

2. **电流采样延迟：**一拍延迟使电流环相位裕度降低，带宽受限，可能导致振荡。

3. **ADC量化误差与噪声：**12位ADC量化步长约0.8mV（3.3V参考），叠加噪声后电流采样精度下降，影响dq解耦。

4. **电机参数变化：**温度导致Rs变化20%以上，磁饱和导致Ls随电流变化，PI参数不再最优。

5. **逆变器非线性：**管压降、开关时间不一致、最小脉宽限制等。

6. **传感器误差：**编码器安装偏心、霍尔元件位置偏差等。

非理想模型仿真通过后，算法在实机上成功的概率大幅提高。

## 快速上手

核心概念&#9660;

#### 环境准备

安装Python 3.8+，通过pip安装emachinery包：`pip install emachinery`。依赖NumPy、SciPy、Matplotlib。Streamlit前端需额外安装：`pip install streamlit`。建议使用虚拟环境隔离依赖。

#### 三种启动方式

**方式1 - CLI直接运行：**`python -m emachinery.sim --config foc.yaml`，适合批量仿真。**方式2 - Streamlit交互：**`streamlit run app.py`，适合参数探索。**方式3 - Python脚本调用：**import emachinery API编程式调用，适合自定义流程。

#### Streamlit操作

左侧边栏选择仿真模式（FOC/六步换相/参数辨识），中间面板调整参数，右侧实时显示波形。支持参数滑块实时调整、波形缩放、数据导出。每次参数变更自动重新仿真并刷新波形。

#### YAML参数速查

仿真参数通过YAML配置文件管理。核心参数分四组：**电机参数**（Rs, Ld, Lq, Flux, J, Bfriction）、**控制参数**（Kp_id, Ki_id, Kp_iq, Ki_iq, Kp_speed, Ki_speed）、**仿真参数**（dt, t_end, PWM_freq）、**工况参数**（speed_ref, load_torque）。

快速上手建议：先用Streamlit交互模式熟悉各参数对波形的影响，建立直觉；再用YAML配置文件做精确参数整定；最后用Python脚本做批量自动化仿真。

练习题 (2)&#9660;

简单YAML配置文件中如何修改电机定子电阻和仿真步长？查看参考参考解答

**修改定子电阻：**在YAML文件的motor段下修改Rs字段。例如将Rs从0.5&Omega;改为0.8&Omega;：

`motor:&emsp;Rs: 0.8&emsp;# 定子电阻 [&Omega;]`

**修改仿真步长：**在simulation段下修改dt字段。例如将步长从1&mu;s改为0.5&mu;s：

`simulation:&emsp;dt: 5.0e-7&emsp;# 仿真步长 [s]`

**注意事项：**

1. 仿真步长dt必须远小于PWM周期（$T_{PWM}=1/f_{PWM}$），通常取dt &le; $T_{PWM}/100$。

2. 步长越小仿真精度越高但耗时越长，需在精度与效率间权衡。

3. Rs变化直接影响电流环PI参数的最优值，修改后需重新整定。

自评：掌握部分未掌握
中等仿真步长如何选择？步长过大或过小分别有什么问题？查看参考参考解答

**步长选择原则：**

1. **Nyquist准则：**dt &le; $1/(2f_{max})$，$f_{max}$为信号最高频率分量。PWM频率10kHz时，$f_{max}$可达数十kHz。

2. **工程经验：**dt &le; $T_{PWM}/100$，即PWM频率10kHz时dt &le; 1&mu;s。

3. **数值稳定性：**对于刚性系统（电气时间常数远小于机械时间常数），步长需小于最小时间常数的1/10。

**步长过大的问题：**

1. 数值不稳定：Euler法可能发散，特别是电感电流计算。

2. PWM边沿丢失：无法精确捕捉开关瞬间，占空比分辨率下降。

3. 电流纹波失真：无法正确反映开关频率纹波。

**步长过小的问题：**

1. 仿真耗时过长：dt从1&mu;s降到0.1&mu;s，耗时增加10倍。

2. 内存占用增大：数据点数量线性增加。

3. 累积舍入误差：浮点运算次数增加，但通常不是主要问题。

**推荐：**PWM 10kHz时取dt=0.5~1&mu;s；20kHz时取dt=0.25~0.5&mu;s。

## 代码概念映射

核心概念&#9660;

#### 仿真源码结构

emachinery仿真源码按功能模块划分：`foc_current_loop()`实现电流环PI调节，`observer_smo()`实现滑模观测器，`svpwm_generate()`实现空间矢量调制，`motor_model_pmsm()`实现PMSM电气/机械方程。

#### 函数与KB模块对照

每个仿真函数对应知识库中的一个或多个理论模块。理解这种映射关系，可以在阅读仿真代码时快速定位理论依据，也可以在学习理论时找到对应的代码实现进行验证。

#### 数据流路径

仿真数据流：角度/速度给定 &rarr; 速度环PI &rarr; iq给定 &rarr; 电流环PI(d/q) &rarr; Vd/Vq &rarr; 反Park变换 &rarr; V&alpha;/V&beta; &rarr; SVPWM &rarr; 电机模型 &rarr; Ia/Ib/Ic &rarr; Clarke变换 &rarr; Park变换 &rarr; Id/Iq反馈。每个环节对应一个函数调用。

#### 代码到实机的迁移

仿真代码与嵌入式代码的核心区别：仿真中时间步进由循环控制，实机中由定时器中断驱动；仿真中角度直接计算，实机中由编码器/观测器获取；仿真中PWM输出为占空比值，实机中写入比较寄存器。

| 仿真函数 | KB模块 | 理论依据 | 关键公式 |
| --- | --- | --- | --- |
| `foc_current_loop()` | KB-06 电流环 | dq解耦PI调节 | $V_d = Kp(I_{d\_ref}-I_d) + Ki\int(I_{d\_ref}-I_d)dt$ |
| `observer_smo()` | KB-05 观测器 | 滑模观测器 | $\hat{E}_\alpha = k \cdot \text{sign}(\hat{I}_\alpha - I_\alpha)$ |
| `svpwm_generate()` | KB-08 SVPWM | 空间矢量调制 | 扇区判断 + 占空比计算 |
| `motor_model_pmsm()` | KB-04 FOC算法 | PMSM电压方程 | $V_d = R_s I_d + L_d \frac{dI_d}{dt} - \omega_e L_q I_q$ |
| `clarke_transform()` | KB-04 FOC算法 | 3相到2相变换 | $I_\alpha = I_a$, $I_\beta = \frac{1}{\sqrt{3}}(I_a + 2I_b)$ |
| `park_transform()` | KB-04 FOC算法 | 静止到旋转变换 | $I_d = I_\alpha\cos\theta + I_\beta\sin\theta$ |

学习建议：先理解KB理论模块的数学推导，再对照仿真代码看如何将公式转化为程序。特别注意：仿真中积分用累加近似（$dt \cdot error$），实机中用梯形积分或抗积分饱和策略。

练习题 (2)&#9660;

简单foc_current_loop()函数对应KB中哪个模块？observer_smo()对应哪个？查看参考参考解答

`foc_current_loop()` 对应 **KB-06 电流环**模块。该函数实现dq轴电流环PI调节器，输入为Id_ref/Iq_ref和Id/Iq反馈，输出为Vd/Vq电压给定。核心理论是PI调节器设计，包括Kp和Ki参数计算、抗积分饱和、解耦补偿等。

`observer_smo()` 对应 **KB-05 观测器**模块。该函数实现滑模观测器（Sliding Mode Observer），通过估计反电动势来获取转子位置角。核心理论是滑模控制理论，包括滑模面设计、抖振抑制、锁相环（PLL）提取角度。

困难仿真代码中的积分运算与实机嵌入式代码中的积分实现有什么区别？如何处理积分饱和？查看参考参考解答

**仿真中的积分：**通常用前向Euler法：`integral += error * dt`，dt为固定仿真步长。由于仿真中dt精确可控且很小，Euler法精度足够。

**实机中的积分：**由定时器中断驱动，中断周期$T_s$固定。常用实现：

1. **前向Euler：**`integral += error * Ts`，最简单但精度最低。

2. **梯形积分：**`integral += (error + prev_error) * Ts / 2`，精度更高。

3. **增量式PI：**避免显式积分，输出增量 = Kp&middot;&Delta;error + Ki&middot;error&middot;Ts。

**积分饱和处理（Anti-Windup）：**

1. **条件积分（Clamping）：**输出饱和时停止积分累加。最常用方法。

2. **Back-calculation：**输出饱和时将超出部分反馈到积分器：`integral += error * Ts + (output_sat - output) / Ki`

3. **积分限幅：**直接限制积分器上下限。

**实机特有问题：**中断抖动导致$T_s$不固定；ADC采样时刻与PWM更新时刻的同步；多轴PI的积分器状态管理。

## 仿真绘图系统

核心概念&#9660;

#### 绘图系统架构

emachinery绘图系统基于Matplotlib，支持**实时绘图**（Streamlit模式下仿真过程中动态刷新）和**离线绘图**（仿真完成后批量渲染）。绘图配置通过YAML文件或API参数控制，支持多子图、双Y轴、自定义颜色和标注。

#### 标准波形组

FOC仿真标准输出6组波形：**三相电流**(Ia/Ib/Ic)、**dq电流**(Id/Iq)、**dq电压**(Vd/Vq)、**转速与转矩**(&omega;/Te)、**角度跟踪**(&theta;_ref vs &theta;_est)、**SVPWM占空比**(Da/Db/Dc)。每组波形独立子图，时间轴对齐。

#### 数据导出

支持导出为**CSV**（通用表格格式，可用Excel/MATLAB读取）、**NPY**（NumPy二进制格式，高效读写大数组）、**JSON**（结构化数据，含元信息）和**HDF5**（大规模数据，支持分块读取）。导出命令：`sim.export('result.csv', format='csv')`

#### 绘图格式

支持输出为**PNG**（位图，适合报告）、**SVG**（矢量图，适合论文）、**PDF**（矢量图，适合打印）和**HTML**（交互式，适合分享）。通过`fig.savefig('plot.svg', format='svg')`指定格式。

分析技巧：观察dq电流波形时，Id应稳定在0（表贴式PMSM），Iq跟踪负载变化；若Id波动大说明解耦不完善或角度误差。观察角度跟踪波形时，稳态误差应趋近0，动态过程中跟踪延迟反映观测器带宽。

## emachinery完整使用教程

核心概念&#9660;

#### emachinery架构

emachinery是基于Python C扩展的高性能电机控制仿真框架。核心层用C实现电机模型和FOC算法（速度比纯Python快100倍），接口层用Python封装，前端层支持CLI和Streamlit两种交互方式。模块化设计，各仿真模式独立。

#### 仿真模式详解

**FOC模式：**完整磁场定向控制链路，支持表贴式/内置式PMSM。**六步换相模式：**方波驱动BLDC，含换相逻辑和PWM调制。**参数辨识模式：**高频注入或阶跃响应法辨识电机参数。**开环模式：**给定角度开环运行，用于验证基础变换和SVPWM。

#### 与Streamlit前端的区别

emachinery核心是仿真引擎（C扩展+Python API），Streamlit是可选的交互式前端。**核心引擎**提供精确的数值计算，可通过CLI或Python脚本调用，适合批量仿真和自动化测试。**Streamlit前端**提供参数滑块、实时波形、模式切换等交互功能，适合参数探索和教学演示。

#### 高级功能

## 数字孪生

核心概念&#9660;

#### 数字孪生定义

数字孪生是物理电机的虚拟映射，通过实时数据同步使虚拟模型与物理实体状态一致。不同于离线仿真，数字孪生强调**实时性**（模型与实体同步运行）、**双向交互**（实体数据驱动模型，模型预测指导实体）和**自进化**（模型参数在线更新）。

#### 参数辨识

从实机运行数据中提取电机参数（Rs, Ld, Lq, &psi;_m, J）。方法包括：**静态测试**（锁定转子测Rs/Ls）、**高频注入**（注入高频电压测电感）、**阶跃响应**（电压阶跃测时间常数）、**在线递推**（RLS/EKF实时估计）。

#### 模型验证

将实机运行数据与仿真模型输出对比，量化模型精度。验证指标：**电流RMSE**（均方根误差  95%）、**动态响应一致性**（上升时间偏差

#### 在线自适应

运行中持续更新模型参数以跟踪物理实体的变化。Rs随温度变化、Ls随磁饱和变化、&psi;_m随退磁变化。通过**模型参考自适应系统(MRAC)**或**扩展卡尔曼滤波(EKF)**实现在线参数估计，更新仿真模型。

仿真置信度评估：置信度 = f(模型精度, 参数辨识精度, 未建模动态影响)。高置信度要求：(1)模型包含关键非理想因素；(2)参数辨识误差 < 5%；(3)未建模动态在关注频段内可忽略。置信度随工况偏离标称点而降低。

&#120791;关键公式&#9660;

$$\hat{R}_s = \frac{V_d - L_d \frac{dI_d}{dt} + \omega_e L_q I_q}{I_d}$$在线Rs辨识。稳态时dId/dt&asymp;0，简化为$\hat{R}_s = (V_d + \omega_e L_q I_q)/I_d$。需Id&ne;0时才可观测。
$$\text{RMSE} = \sqrt{\frac{1}{N}\sum_{k=1}^{N}(y_{real}(k) - y_{sim}(k))^2}$$模型验证均方根误差。N为采样点数，y为被验证的物理量（电流/转矩/转速）。RMSE < 5%额定值为优。
$$\hat{\theta}_{k+1} = \hat{\theta}_k + K_k(z_k - h(\hat{\theta}_k))$$EKF参数更新。$\theta$为待估参数向量，K为Kalman增益，z为测量值，h为观测函数。实现参数在线自适应。

中等数字孪生的核心挑战是什么？参数辨识需要满足什么激励条件？查看参考参考解答

**数字孪生的核心挑战：**

1. **模型-实体一致性：**物理系统存在磨损、老化、环境变化，模型必须持续更新才能保持一致。一次性标定的模型置信度随时间衰减。

2. **参数可辨识性：**并非所有参数都能从外部可测信号中辨识。例如Id=0控制下Rs不可辨识（Id方程退化为0=0）。

3. **实时性要求：**模型更新速度需跟上物理系统变化速度。温度变化较慢（秒级），磁饱和变化较快（毫秒级）。

4. **传感器限制：**实机可测信号有限（通常只有电流和位置），需从有限信息推断完整状态。

5. **计算资源约束：**在线自适应算法（EKF/RLS）的计算量需在嵌入式平台实时完成。

**参数辨识的激励条件：**

1. **持续激励(PE)条件：**输入信号必须包含足够丰富的频率成分，使待辨识参数可观测。直流激励只能辨识Rs，高频激励才能辨识Ls。

2. **信噪比要求：**激励信号幅度需足够大，使响应信号高于噪声水平。但过大会引起非线性或饱和。

3. **稳态与动态结合：**Rs辨识需稳态数据（dI/dt=0），Ls辨识需动态数据（dI/dt&ne;0），需两种工况交替运行。

4. **独立激励：**各参数的激励信号需相互独立，避免参数耦合导致辨识结果不唯一。
