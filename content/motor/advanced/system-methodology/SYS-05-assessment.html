SYS-05 功能安全：电控系统的生命线 - 检验题目 ​

模块编号： SYS-05 题目数量： 13题 题型分布： 概念理解8题（选择题）+ HARA分析2题 + FMEA表格2题 + 安全状态设计1题 难度分布： 基础4题 / 进阶5题 / 综合4题

第一部分：概念理解（单项选择题，A/B/C/D） ​

第1题：功能安全的本质 ​

题目： 关于功能安全的本质，以下理解最准确的是？

A. 功能安全就是给系统加保护电路和看门狗

B. 功能安全是一套系统化的工程方法论，核心是证明保护措施足够

C. 功能安全就是通过安全认证拿到证书

D. 功能安全就是按照ISO 26262写文档

正确答案： B

详细解析：

功能安全的本质不是"加保护"，而是"证明保护足够"。这要求工程师从定性思维转变为定量思维——不仅要设计保护措施，还要量化诊断覆盖率、计算硬件度量、验证残余风险可接受。

  • 选项A： "加保护"只是手段，不是目的。加了保护但无法证明其充分性，在安全审计面前毫无意义。
  • 选项B： 正确。功能安全是一套从危害分析到安全确认的完整方法论，每一步都有标准可依、有数据可查。
  • 选项C： 认证是结果，不是目的。为了认证而认证，往往导致文档与实现脱节。
  • 选项D： ISO 26262是方法论框架，不是"写文档"。文档只是证据载体，核心是工程实践。

第2题：ASIL等级的决定因素 ​

题目： 同一个电机控制器，用在车载空调风机上评估为QM，用在电动汽车驱动系统上评估为ASIL-D。这说明ASIL等级由什么决定？

A. 由产品的技术复杂度决定

B. 由危害场景的严重度、暴露率和可控性决定

C. 由MCU的性能和冗余设计决定

D. 由客户的预算和安全投入决定

正确答案： B

详细解析：

ASIL等级由HARA分析确定，HARA的三个维度是严重度(S)、暴露率(E)、可控性(C)。同一个产品在不同应用场景下，这三个维度可能完全不同。

  • 选项A： 技术复杂度与ASIL等级无直接关系。一个简单的刹车开关可以是ASIL-D，一个复杂的娱乐系统可能只是QM。
  • 选项B： 正确。风机失控最多吹风不舒服（S1, C0→QM），驱动电机失控可导致致命事故（S3, E4, C3→ASIL-D）。
  • 选项C： MCU选型是ASIL等级确定后的设计决策，不是ASIL等级的决定因素。
  • 选项D： 安全等级不能因预算不足而降低。如果成本无法满足ASIL要求，应重新评估系统架构。

第3题：过流保护的诊断覆盖率 ​

题目： 某电机控制器仅使用软件过流检测（ADC采样+阈值比较+延时确认），其诊断覆盖率约为90%。客户要求ASIL-B（SPFM≥97%），以下改进方案最有效的是？

A. 增加软件滤波，降低误检率

B. 增加硬件比较器直接封锁PWM，与软件检测形成双冗余

C. 降低过流阈值，提高灵敏度

D. 增加过流检测的延时确认时间

正确答案： B

详细解析：

诊断覆盖率(DC)衡量的是"故障发生时能被检测到的概率"。提高DC需要增加检测手段的覆盖面，而非调整已有手段的参数。

  • 选项A： 降低误检率提高的是"检测准确性"，不是诊断覆盖率。误检率和漏检率是两个概念——DC关注的是漏检率。
  • 选项B： 正确。硬件比较器能检测软件无法检测的故障（如ADC失效、MCU程序跑飞导致软件检测不执行），两者组合DC可达97%以上。硬件比较器覆盖的故障模式与软件检测互补。
  • 选项C： 降低阈值提高灵敏度，但可能增加误检率，且不增加对"检测手段本身失效"的覆盖。
  • 选项D： 增加延时确认反而降低了响应速度，且不提高DC。

第4题：安全状态设计 ​

题目： 电动汽车驱动电机在行驶中发生非预期加速故障，以下安全状态序列最合理的是？

A. 立即关闭PWM→电机高阻态→车辆自由滑行停止

B. 立即施加制动转矩→减速至安全速度→关闭PWM→高阻态

C. 立即切断整车电源→所有系统停止

D. 限制电机最大转矩→继续行驶→请求驾驶员停车

正确答案： B

详细解析：

安全状态设计必须考虑"从故障到安全"的过渡过程，而非简单地"关机了事"。

  • 选项A： 直接关PWM（高阻态）意味着电机失去所有转矩，但车辆仍在高速运动。在高速下自由滑行，制动距离长，且可能追尾。这不是"安全状态"，而是"放弃控制"。
  • 选项B： 正确。先利用电机本身的制动能力（施加反向电流）快速减速，待速度降到安全范围后再关PWM。这充分利用了电机的主动制动能力，是最安全的过渡方案。
  • 选项C： 切断整车电源会导致转向助力、刹车助力同时丧失，反而更危险。安全状态应保持辅助系统运行。
  • 选项D： 非预期加速时继续行驶不可接受——FTTI要求在100-200ms内进入安全状态。

第5题：FTTI的理解 ​

题目： 某电机控制器的过流保护FTTI为50μs，以下说法正确的是？

A. 从过流发生到软件检测到故障的时间不超过50μs

B. 从过流发生到系统进入安全状态的总时间不超过50μs

C. 从过流发生到PWM被封锁的时间不超过50μs

D. 看门狗的超时时间设置为50μs

正确答案： B

详细解析：

FTTI（Fault Tolerant Time Interval）是从故障发生到系统必须进入安全状态的最大允许时间。它是一个端到端的时间约束，包括检测时间+响应时间+执行时间。

  • 选项A： 检测时间只是FTTI的一部分，还需要加上响应和执行时间。
  • 选项B： 正确。FTTI是端到端约束：故障发生→检测→判断→执行安全状态，全流程必须在50μs内完成。对于过流保护，这意味着必须用硬件比较器直接封锁PWM（软件无法在50μs内完成全流程）。
  • 选项C： PWM封锁是安全状态的执行动作，但FTTI是从故障发生开始计算的完整时间。
  • 选项D： 看门狗超时时间通常远大于FTTI（ms级vs μs级），两者是不同的概念。

第6题：双核锁步 ​

题目： 关于双核锁步MCU，以下说法错误的是？

A. 两个核执行相同的指令流，每个时钟周期比较输出

B. 双核锁步可以检测CPU内部寄存器的单点故障

C. 双核锁步MCU的计算能力是普通MCU的两倍

D. ASIL-D通常要求使用双核锁步MCU

正确答案： C

详细解析：

双核锁步的两个核执行相同的代码，因此计算能力与单核相同，而非两倍。第二个核是"检查核"，不承担额外计算任务。

  • 选项A： 正确描述。两个核同步执行，比较器实时检查输出一致性。
  • 选项B： 正确描述。如果Core 0的ALU寄存器损坏导致计算错误，Core 1的计算结果会不同，比较器立即检测到。
  • 选项C： 错误。两个核做同样的事，计算能力不增加。如果需要额外算力，需要使用非锁步的第三个核（如Infineon Aurix的Core 2）。
  • 选项D： 正确描述。ASIL-D要求单点故障度量≥99%，普通单核MCU的CPU故障无法自检，必须使用锁步架构。

第7题：看门狗选择 ​

题目： 某ASIL-C的电机控制器，需要选择看门狗方案。以下方案最合适的是？

A. 独立看门狗(IWDG)，超时时间100ms

B. 窗口看门狗(WWDG)，窗口5~10ms

C. 问答看门狗(Q&A WDG)，每次控制周期回答一个问题

D. 不需要看门狗，用软件自检代替

正确答案： C

详细解析：

ASIL-C要求看门狗必须具备"检测程序跑飞后仍在正确时间喂狗"的能力。普通看门狗和窗口看门狗都无法做到这一点——程序跑飞后可能碰巧在正确时间喂狗。

  • 选项A： 独立看门狗只能检测"程序完全停止"，无法检测"程序跑飞但仍在喂狗"的情况。ASIL-C不够。
  • 选项B： 窗口看门狗比独立看门狗更严格（必须在窗口内喂狗），但仍无法防止程序跑飞后碰巧在窗口内喂狗。
  • 选项C： 正确。问答看门狗要求软件根据问题计算答案，程序跑飞后无法正确计算，即使碰巧在正确时间回复，答案也是错的。这是ASIL-C/D推荐的方式。
  • 选项D： 软件自检无法检测"软件本身跑飞"的情况——这是看门狗存在的根本原因。

第8题：SPFM计算 ​

题目： 某系统有3个安全相关元器件，故障率和诊断覆盖率如下：

元器件λSP (FIT)DC
MCU内核1099%
电流采样2090%
PWM驱动5095%

计算SPFM，并判断是否满足ASIL-B（≥97%）？

A. SPFM = 94.25%，不满足ASIL-B

B. SPFM = 97.0%，刚好满足ASIL-B

C. SPFM = 98.5%，满足ASIL-B

D. SPFM = 99.0%，满足ASIL-B

正确答案： A

详细解析：

SPFM = 1 - Σ(λSPi·(1-DCi)) / Σ(λSPi)

计算过程：

  • MCU内核：10 × (1-0.99) = 10 × 0.01 = 0.1 FIT
  • 电流采样：20 × (1-0.90) = 20 × 0.10 = 2.0 FIT
  • PWM驱动：50 × (1-0.95) = 50 × 0.05 = 2.5 FIT
  • Σ(λSPi·(1-DCi)) = 0.1 + 2.0 + 2.5 = 4.6 FIT
  • Σ(λSPi) = 10 + 20 + 50 = 80 FIT
  • SPFM = 1 - 4.6/80 = 1 - 0.0575 = 94.25%

ASIL-B要求SPFM ≥ 97%，94.25% < 97%，不满足。

改进方向：电流采样的DC=90%是主要瓶颈（贡献2.0/4.6=43.5%的残余故障率），需要提高其诊断覆盖率至97%以上。

1. HARA评估：

维度等级理由
严重度(S)S2(重伤)25km/h突然加速可导致骑行者摔倒重伤，但通常不致命

第10题：工业机器人关节驱动HARA ​

题目： 某工业机器人关节驱动电机（最大转速3000rpm，最大转矩50Nm），可能发生"电机突然输出最大转矩"的危害事件。请完成HARA分析。

要求：

  1. 评估严重度(S)、暴露率(E)、可控性(C)
  2. 确定ASIL等级
  3. 分析安全状态选择（高阻态 vs 短路制动 vs 主动制动）

参考答案：

1. HARA评估：

维度等级理由
严重度(S)S3(致命)50Nm突然转矩可导致机械臂猛烈运动，碾压附近人员
暴露率(E)E3(经常)工业机器人长时间运行，人员可能在附近维护
可控性(C)C3(不可控)人员无法对抗50Nm的机械臂运动

2. ASIL等级：S3×E3×C3 → 查表得 ASIL-D

3. 安全状态分析：

安全状态适用性分析
高阻态不适用电机自由减速，但机械臂可能在重力作用下继续运动，危险
短路制动部分适用快速制动，但制动转矩不可控，可能导致机械冲击
主动制动最优施加可控的制动转矩，平滑减速到安全位置后保持

推荐安全状态：主动制动→减速至安全位置→位置保持（伺服锁定）→高阻态

第13题：电动工具电机控制器安全状态设计 ​

2. 非预期运转安全状态时序：

text
T=0ms:    用户松开扳机，但电机未停止
          → 软件检测到扳机信号=0但电机仍在运转
T=5ms:    软件设置故障标志
          → 状态机转入FAULT
T=5ms:    FAULT进入函数执行
          → 关闭PWM输出（高阻态）
          → 电机自由减速
T=5ms:    上报故障码
          → LED闪烁报警
T=1~3s:   电机停止
          → 等待故障复位（重新上电）

3. 过流保护安全状态时序：

text
T=0μs:    电流超过硬件阈值
          → 硬件比较器触发BRK引脚
          → PWM立即封锁（μs级）
T=0.1ms:  软件过流检测确认
          → 设置故障标志
          → 状态机转入FAULT
T=0.1ms:  FAULT进入函数执行
          → 下桥臂全导通（短路制动）
          → 记录故障码
T=0.5ms:  电机快速减速
T=0.5~2s: 电机停止
          → 切换到高阻态

4. 硬件与软件分工：

功能硬件实现软件实现理由
过流快速保护比较器+BRK引脚响应不够快FTTI=50μs，软件无法保证
过流延时确认灵活性差可编程阈值+延时避免瞬态误触发
非预期运转检测逻辑复杂扳机信号+转速判断FTTI=100ms，软件可实现
看门狗硬件看门狗软件无法自检程序跑飞时软件不可信
安全状态执行PWM封锁（硬件BRK）短路制动（软件控制）硬件保证最快响应，软件提供精细控制
故障记录无存储能力写入Flash/EEPROM软件负责记录和上报

评分细则 ​

概念理解题（第1~8题）：

  • 选对得5分，选错得0分
  • 无半对分数

HARA分析题（第9~10题）：

  • S/E/C评估合理且有理由：每项3分，共9分
  • ASIL等级正确：3分
  • 安全措施合理：3分（每条1.5分）

FMEA表格题（第11~12题）：

  • 每行（失效模式+影响+检测+DC）：2分
  • 至少5行，共10分
  • DC估计合理即可，不要求精确

  • 危害事件识别：3分
  • 安全状态设计：3分
  • 时序设计：2分
  • 硬件/软件分工：2分

学习建议 ​

按等级的改进方向 ​

A级（90~100）：

  • 深入学习ISO 26262 Part 5（硬件安全）和Part 6（软件安全）
  • 尝试完成一个完整的FMEA分析项目
  • 学习故障注入测试方法

B级（75~89）：

  • 加强HARA分析的实践，多做不同场景的练习
  • 重点理解SPFM/LFM/PMHF的计算方法和改进策略
  • 学习FTA（故障树分析）方法，与FMEA互补

C级（60~74）：

  • 重新学习本模块第4节（技术原理），重点关注4.2~4.6节
  • 理解ASIL等级矩阵的使用方法
  • 练习SPFM计算，至少完成3组不同数据的计算

D级（<60）：

  • 建议先学习ISO 26262 Part 1（概述）和Part 3（概念阶段）
  • 理解功能安全的基本术语：危害、风险、安全目标、安全状态
  • 从简单的过流保护案例开始，逐步理解功能安全的思维方式

推荐学习路径 ​

text
第1步：理解概念（本模块第1~3节）

  → 完成2~3个不同场景的HARA分析练习

  → 完成SPFM/LFM/PMHF的计算练习

  → 设计不同场景的安全状态序列

  → 完成一个完整的电机控制器安全分析案例
